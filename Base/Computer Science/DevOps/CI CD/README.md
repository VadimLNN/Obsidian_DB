## Исправления и границы достоверности

Оригинал не редактируется. Следующие утверждения уточнены в производных конспектах:

| Упрощение исходника | Корректная трактовка |
|---|---|
| «Тесты прошли — код рабочий», «Docker гарантирует работу в production» | Проверено только заданное поведение в конкретных условиях; данные, нагрузка, права и сеть могут отличаться |
| «Каждая job изолирована», «GitLab запустит контейнер» | Это зависит от executor; Shell работает на хосте |
| «Pipeline останавливается при первой ошибке» | Зависимые обязательные этапы блокируются; уже работающие jobs, cleanup и allowed failures имеют отдельные правила |
| build `myapp:SHA`, push `registry.example.com/myapp:SHA` | Это разные ссылки на образ; build и push должны использовать одно полное имя либо нужен `docker tag` |
| Staging и production в одном stage | Они не образуют последовательность автоматически; нужен отдельный stage или явная зависимость |
| `only/except` как основной современный механизм | В курсе он есть; новые примеры используют `rules`, старый синтаксис объяснён в шпаргалке |
| Docker безопасен для любого недоверенного кода | Общее ядро, privileges, mounts и Docker socket могут открыть доступ к хосту |
| «Добавить dind и DOCKER_HOST» решает любой сбой Docker | Нужны корректные executor, daemon, TLS, сеть и права; dind не требуется для обычного `image` |
| «GitHub Actions бывает только в облаке» | Есть self-hosted runners и GitHub Enterprise Server; см. [документацию GitHub](https://docs.github.com/en/enterprise-server%403.18/actions/concepts/runners/self-hosted-runners) |
| Argo CD всегда исправляет ручной drift | Автоматический sync и self-heal настраиваются отдельно |
| Kubernetes обязателен для Continuous Deployment | Это свойство процесса, а не обязательный стек; реализация возможна и на VM |
| Blue Ocean как текущий вариант интерфейса Jenkins | С июля 2026 он deprecated и не получает исправлений безопасности; см. [статус Blue Ocean](https://www.jenkins.io/doc/book/blueocean/) |

Числа о NPS, окупаемости, частоте релизов компаний и «нормальном проценте зелёных сборок» в оригинале не сопровождаются проверяемыми первоисточниками. Они не используются как доказательства или нормативы. Количество каналов между `n` участниками — `n(n−1)/2`, квадратичный, а не экспоненциальный рост. В примере параллельности `max(5,2,3) + 5 + 3 = 13` минут, а не 8.

Тарифы, квоты, доступность сервисов по странам и юридические требования не переносятся как постоянные факты. Их нужно проверять для конкретного продукта, договора и ситуации. Self-hosted сам по себе не гарантирует безопасность или отсутствие исходящего трафика.

## Дополнительно к курсу

Добавлены для практической полноты: жизненный цикл runner и различия executors; `workflow:rules`; явный блокирующий manual job; срок хранения artifacts; кэш npm по lock-файлу; защита SSH host key; последовательные деплои через `resource_group`; минимальный проект, проверки HTTP и задания с ожидаемым результатом. Docker Compose используется как короткая реализация обновления сервиса: в курсе Compose упоминается, но готового CD-примера на нём нет.

Это дополнения, а не выданные за лекции части курса. Kubernetes, Helm, Istio, Tekton, Flux, Fleet, Vault и расширенный GitOps остаются направлениями дальнейшего изучения.
