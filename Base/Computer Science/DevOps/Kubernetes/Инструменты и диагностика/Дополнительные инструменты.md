## Lens

[Lens](https://k8slens.dev/) — графический инструмент работы с Kubernetes: просмотр ресурсов и их состояния, навигация между объектами и операции управления.

![](https://ucarecdn.stepik.net/831bf4be-f7d5-40a0-aecc-0a13325dc114/)

GUI помогает исследовать кластер, но не заменяет понимание API и проверку через `kubectl get/describe/logs`. Интерфейс может показывать устаревшее состояние из кэша, а доступные действия определяются правами kubeconfig. При cluster-admin ошибочная операция столь же опасна, как команда терминала с теми же правами.

## ktx, kns и shell aliases

`ktx` упрощает смену contexts, `kns` — namespace текущего context. Ссылка на реализацию: [blendle/kns](https://github.com/blendle/kns). Перед использованием стороннего бинарника проверяются происхождение и совместимость.

![](https://ucarecdn.stepik.net/63ae10a8-7ad3-4564-bff5-e28e97241181/)

Aliases сокращают команды, но не меняют их действие и права. Пример для Bash (`.bashrc`):

```bash
alias k='kubectl'
alias kgp='kubectl get pods'
alias kdp='kubectl describe pod'
alias kl='kubectl logs'
alias kpf='kubectl port-forward'
alias kgrq='kubectl get resourcequota'
alias kgcm='kubectl get cm'
alias kgs='kubectl get secrets'
alias kgsrv='kubectl get service'
alias kgd='kubectl get deployment'
alias kgrs='kubectl get rs'
alias kg='kubectl get'
alias kgi='kubectl get ingress'
alias kd='kubectl describe'
alias kgn='kubectl get nodes'
alias kgss='kubectl get statefulset'
alias kgnp='kubectl get networkpolicies.crd.projectcalico.org'
alias kgns='kubectl get networksets.crd.projectcalico.org'
alias kgvs='kubectl get virtualservices.networking.istio.io'
alias kdvs='kubectl describe virtualservices.networking.istio.io'
```

Исправлены опечатки `kubectl port forward` → `kubectl port-forward` и `kubectl det service` → `kubectl get service`. Calico/Istio aliases работают только при наличии соответствующих CRD. В частности, `kgns` в этом наборе означает Calico NetworkSets, а не namespaces.

## Shell-функции для exec и сохранения логов

Первый аргумент функций — реальное имя Pod, далее допускаются kubectl flags, например `-n example-app`. Примеры рассчитаны на Bash:

```bash
kex() {
  local pod=${1:?Pod name required}
  shift
  kubectl exec -it "$pod" "$@" -- sh -c 'command -v bash >/dev/null && exec bash; command -v ash >/dev/null && exec ash; exec sh'
}

kexi() {
  local pod=${1:?Pod name required}
  shift
  kubectl exec -it "$pod" -c istio-proxy "$@" -- sh
}

klf() {
  local pod=${1:?Pod name required}
  shift
  local log_dir=${DEBUG_DIR:-./debug}
  mkdir -p "$log_dir" || return
  kubectl logs "$pod" "$@" > "$log_dir/$pod.log"
}

klfp() {
  local pod=${1:?Pod name required}
  shift
  local log_dir=${DEBUG_DIR:-./debug}
  mkdir -p "$log_dir" || return
  kubectl logs "$pod" --previous "$@" > "$log_dir/$pod-previous.log"
}
```

`kex` требует хотя бы `sh` в контейнере. `kexi` имеет смысл только для Pod с контейнером `istio-proxy` и shell внутри него; для distroless-образа нужна иная диагностика. Наличие контейнера не гарантируется самим Istio alias.

`klf` сохраняет текущие логи, `klfp` — предыдущего экземпляра контейнера после restart. В старом варианте `klfp` отсутствовал `--previous`, поэтому имя файла вводило в заблуждение. Используется нейтральный локальный каталог и расширение `.log`: приложение не обязано писать JSON. При повторе файл с тем же именем перезаписывается; для сохранения нескольких снимков задаётся новый `DEBUG_DIR`.
