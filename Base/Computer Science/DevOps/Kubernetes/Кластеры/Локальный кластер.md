# Локальный кластер

[[Kubernetes|Карта тем]] · [[kubectl]] · [[Self-hosted и Managed Kubernetes]]

## Minikube

Minikube создаёт локальный Kubernetes-кластер для экспериментов, проверки манифестов и освоения API. Обычный начальный вариант — одна Node; Minikube также поддерживает многоузловые конфигурации. Узлы могут работать в контейнерах или виртуальных машинах в зависимости от driver.

Одна Node может совмещать control-plane компоненты и workloads. Такой стенд не моделирует полноценную отказоустойчивость production-кластера. HA требует устранения единственных точек отказа, доступности API и кворума etcd; число машин зависит от топологии, а не от универсального требования «любому Kubernetes нужны ровно три VM».

`kubectl` — клиент Kubernetes API, не сам кластер. Для работы требуется context с endpoint и credentials локального API. [[kubectl#Контексты и namespace]] описывает проверку выбранного окружения перед командами.

## Сеть и доступ к приложениям

| Задача | Механизм |
|---|---|
| Получить адрес Node | `minikube ip` |
| Проверить Pod/Service с компьютера | `kubectl port-forward` |
| Получить URL NodePort | `minikube service --url -n example-app example-nodeport` |
| Обеспечить локальный доступ к LoadBalancer | `minikube tunnel` |
| Проверить исторический nginx ingress addon | `minikube addons enable ingress`, с оговоркой из [[Ingress]] |

Driver влияет на достижимость IP Node. При Docker driver на некоторых ОС требуется туннель; процесс туннеля должен оставаться запущенным. Имя Docker network зависит от профиля. Вложенная виртуализация, VPN и маршруты хоста могут мешать доступу даже при исправных Pod.

Полные манифесты и варианты проверок находятся в [[Pod]], [[Service]] и [[Ingress]]. Установка Minikube и выбор driver зависят от ОС и среды; универсальная инструкция установки из одного исходного абзаца не выводится.

## Границы локального стенда

Локальный успех подтверждает работу в данной конфигурации, но не проверяет HA, облачные балансировщики, security groups и production-storage. Kind и k3d — другие варианты локального Kubernetes, перечисленные в общем плане; отдельные руководства по ним здесь не создаются без исходного материала.

Документация: [доступ к приложениям Minikube](https://minikube.sigs.k8s.io/docs/handbook/accessing/).
