# Процессы и сигналы

[[OS/Linux/Linux|Карта Linux]]

## Процессы

Процессы — фундаментальная часть Linux.

Roadmap подчёркивает:

> понимание процессов = понимание того, почему сервис упал, почему сервер тормозит и как это чинить.

### `ps aux`

Показать снимок процессов системы.

```bash
ps aux
```

### PID

PID — уникальный идентификатор процесса.

Пример:

```text
PID 1234
```

### `kill`

Отправить сигнал процессу.

```bash
kill 1234
```

### `kill -9`

Принудительно завершить процесс.

```bash
kill -9 1234
```

Это отправляет `SIGKILL`.

## Состояния процессов

В roadmap выделены основные состояния.

| Состояние | Код | Что означает |
|---|---|---|
| Running | `R` | процесс выполняется |
| Sleeping | `S` | процесс спит и ждёт |
| Uninterruptible | `D` | процесс ждёт I/O |
| Zombie | `Z` | процесс завершён, но запись о нём осталась |
| Stopped | `T` | процесс остановлен |

### Zombie-процесс

Zombie:

```text
процесс уже завершился,
но запись о нём всё ещё существует в таблице процессов
```

Это частый вопрос на собеседованиях.

## Жизненный цикл процесса

Roadmap рекомендует разобраться в:

```text
fork()
exec()
wait()
```

Общая идея:

```text
процесс
   ↓
fork()
   ↓
создание нового процесса
   ↓
exec()
   ↓
запуск другой программы
   ↓
wait()
   ↓
ожидание завершения дочернего процесса
```

## Сигналы процессов

Linux использует сигналы для управления процессами.

Основные сигналы из roadmap:

| Сигнал | Номер | Назначение |
|---|---:|---|
| `SIGTERM` | 15 | нормальное завершение |
| `SIGKILL` | 9 | принудительное завершение |
| `SIGHUP` | 1 | hangup / часто используется для перечитывания конфигурации |
| `SIGINT` | 2 | прерывание, обычно Ctrl+C |
| `SIGUSR1` | 10 | пользовательский сигнал |
| `SIGUSR2` | 12 | пользовательский сигнал |

## Приоритеты процессов

Roadmap рекомендует изучить:

```text
nice
renice
```

Они связаны с приоритетами планировщика.

```bash
nice command
```

```bash
renice ...
```

Главное — понимать, что процессы могут иметь разные приоритеты планирования.

## Фоновые процессы

Нужно знать:

```text
&
nohup
disown
screen
tmux
```

### `&`

Запустить процесс в фоне.

```bash
python app.py &
```

### `nohup`

Позволяет процессу продолжать работу после выхода из терминала.

```bash
nohup python app.py &
```

### `screen` / `tmux`

Позволяют создавать терминальные сессии и возвращаться к ним позже.

## `/proc`

`/proc` — [[Структура каталогов Linux|псевдофайловая система]].

В ней находится информация:

- о ядре;
- о процессах;
- о состоянии системы.

Например:

```bash
ls /proc
```

У каждого процесса есть каталог:

```text
/proc/<PID>
```

Например:

```bash
ls /proc/1234
```

Roadmap отмечает, что `ps` и `htop` получают информацию о процессах именно через `/proc`.

## Процессы и сигналы

Один из важнейших разделов Linux для DevOps.

### Нужно понимать

- процесс;
- PID;
- PPID;
- parent / child process;
- foreground / background process;
- zombie process;
- жизненный цикл процесса;
- `fork()` → `exec()` → `wait()` на концептуальном уровне.

### Команды

```bash
ps aux
ps -ef
pgrep
pkill
kill
killall
top
htop
jobs
bg
fg
nohup
nice
renice
```

### Основные сигналы

```text
SIGTERM  15 — корректное завершение
SIGKILL   9 — принудительное завершение
SIGHUP    1 — hangup / часто используется для reload
SIGINT    2 — Ctrl+C
SIGSTOP  19 — остановить процесс
SIGCONT  18 — продолжить процесс
```

Важно:

```bash
kill PID
```

обычно отправляет `SIGTERM`, а не «убивает процесс мгновенно».

### Состояния процессов

```text
R — Running
S — Sleeping
D — Uninterruptible sleep
Z — Zombie
T — Stopped
```

### Практика

- [ ] Запустить `sleep 1000`.
- [ ] Найти его PID.
- [ ] Завершить через SIGTERM.
- [ ] Запустить ещё раз и завершить SIGKILL.
- [ ] Запустить процесс в фоне через `&`.
- [ ] Использовать `jobs`, `fg`, `bg`.
- [ ] Запустить процесс через `nohup`.
- [ ] Посмотреть дерево процессов.

#### Мини-эксперимент

```bash
sleep 1000 &
PID=$!
cat /proc/$PID/status
cat /proc/$PID/cmdline
ls -l /proc/$PID/fd
```

Нужно понять, что `/proc` — это псевдофайловая система с информацией о ядре и процессах.
