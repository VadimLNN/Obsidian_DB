# Ресурсы и диагностика

[[OS/Linux/Linux|Карта Linux]]

## OOM Killer

OOM:

```text
Out Of Memory
```

Если системе не хватает RAM, Linux может выбрать процесс и завершить его.

Это делает OOM Killer.

Roadmap также упоминает:

```text
oom_score_adj
```

С его помощью можно влиять на вероятность выбора процесса в качестве жертвы.

Тема важна ещё и потому, что пересекается с [[Requests, Limits и QoS|Kubernetes]].

## Мониторинг ресурсов

Главная базовая команда:

```bash
top
```

или:

```bash
htop
```

`htop` удобнее, но может быть установлен не везде.

## Load Average

В `top` можно увидеть:

```text
load average
```

Это средняя нагрузка за:

```text
1 минуту
5 минут
15 минут
```

Это один из наиболее популярных вопросов по Linux на собеседованиях.

## CPU в `top`

Основные показатели из roadmap:

| Поле | Значение |
|---|---|
| `us` | CPU-время пользовательских процессов |
| `sy` | CPU-время системных вызовов |
| `wa` | I/O Wait — ожидание диска |
| `si` | системные прерывания |
| `id` | простой CPU |

## Память

Roadmap рекомендует понимать:

```text
RSS
VSZ
shared memory
page cache
swap
free -h
```

### `free -h`

Показать использование памяти.

```bash
free -h
```

Особенно важно понимать:

```text
available ≠ free
```

## Диагностика системы

Roadmap предлагает изучить:

```text
vmstat
iostat
sar
dstat
pidstat
```

Они используются для более глубокой диагностики ресурсов.

## `strace`

`strace` показывает системные вызовы процесса.

Roadmap описывает идею так:

> когда процесс делает что-то непонятное, strace позволяет увидеть его действия на уровне системных вызовов.

Пример:

```bash
strace command
```

## `ltrace`

Похожая диагностическая утилита, но ориентирована на библиотечные вызовы.

```bash
ltrace command
```

## Perf

Roadmap рекомендует обзорно познакомиться с:

```text
perf top
perf record
flamegraphs
```

Это уже более глубокий уровень профилирования производительности.

## CPU, RAM, Load Average и диагностика ресурсов

### Главные команды

```bash
top
htop
free -h
uptime
vmstat
iostat
pidstat
```

Не все утилиты могут быть установлены по умолчанию.

### Нужно понимать

#### Load Average

Обычно показывается за:

```text
1 минута / 5 минут / 15 минут
```

Нельзя оценивать load average без количества CPU cores.

Проверь:

```bash
nproc
uptime
```

#### CPU

В `top` обратить внимание на:

```text
us — user CPU
sy — system CPU
wa — I/O wait
id — idle
si — software interrupts
```

#### RAM

Понимать:

- free;
- used;
- available;
- page cache;
- swap;
- RSS;
- VSZ.

Важно: маленькое значение `free` само по себе не означает нехватку памяти.

### OOM Killer

Разобраться:

- что происходит при нехватке RAM;
- почему Linux может убить процесс;
- где искать информацию об OOM;
- что такое `oom_score` и `oom_score_adj`.

Пример поиска:

```bash
journalctl -k | grep -i oom
```

### Практика

- [ ] Посмотреть load average.
- [ ] Сопоставить его с количеством CPU cores.
- [ ] Найти процесс с максимальным CPU.
- [ ] Найти процесс с максимальным RAM.
- [ ] Посмотреть `free -h` и объяснить `available`.
- [ ] Запустить `vmstat 1` и посмотреть систему в динамике.
