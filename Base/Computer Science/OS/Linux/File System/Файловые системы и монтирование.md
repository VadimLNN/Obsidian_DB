# Файловые системы и монтирование

[[OS/Linux/Linux|Карта Linux]] · Источник: Terminal Tools Курс

## Команда `mount` — информация о смонтированных файловых системах

Без аргументов `mount` выводит список всех смонтированных файловых систем.

```bash
mount                # вывести все точки монтирования
```

Вывод содержит много информации, часто используется в сочетании с `grep` для фильтрации:

```bash
mount | grep ext4    # показать только разделы с ext4
```

> [!warning] Требует проверки
> `mkfs.ext4 /dev/sdb1` создаёт новую файловую систему и уничтожает существующие данные на выбранном разделе. Выполняйте пример только на проверенном пустом учебном разделе после резервного копирования. Создание раздела описано в [[OS/Linux/File System/Диски и разделы]].

## Создание файловой системы — `mkfs`

На созданном разделе необходимо создать файловую систему:

```bash
sudo mkfs.ext4 /dev/sdb1
```

## Монтирование раздела

### Создание точки монтирования

Точка монтирования создаётся в папке `/mnt`:

```bash
sudo mkdir /mnt/newdrive
```

### Ручное монтирование

```bash
sudo mount /dev/sdb1 /mnt/newdrive
```

После этого команда `df -h` отобразит новый раздел.

> [!warning] Требует проверки
> `chmod o+w /mnt/newdrive` даёт запись всем «остальным» пользователям и при наличии `x` позволяет удалять чужие записи в каталоге без sticky bit. Для личного или группового диска назначайте конкретного владельца/группу и необходимые права: [[OS/Linux/Administration/Владельцы файлов]], [[OS/Linux/Administration/Специальные права и umask]].

## Настройка прав доступа

По умолчанию новый раздел доступен только root. Чтобы обычные пользователи могли записывать файлы, необходимо изменить права:

```bash
sudo chmod o+w /mnt/newdrive
```

Теперь все пользователи могут писать на новый диск.


## Итог: подключение нового диска

Полный цикл подключения нового диска:

|Шаг|Команда / Действие|
|---|---|
|1|Добавить диск в VirtualBox (выключенная ВМ)|
|2|`lsblk` — убедиться, что диск (`sdb`) обнаружен|
|3|`sudo gdisk /dev/sdb` — создать раздел (`n`, `w`)|
|4|`sudo mkfs.ext4 /dev/sdb1` — создать файловую систему|
|5|`sudo mkdir /mnt/newdrive` — создать точку монтирования|
|6|`sudo mount /dev/sdb1 /mnt/newdrive` — примонтировать|
|7|`sudo chmod o+w /mnt/newdrive` — дать права на запись|

После перезагрузки монтирование нужно будет выполнить заново (если не прописано в `/etc/fstab`).


## Проблема: диск не сохраняется после перезагрузки

После ручного монтирования диск доступен только до перезагрузки системы. При перезагрузке (`reboot`) раздел размонтируется, и его нужно монтировать заново:

```bash
sudo mount /dev/sdb1 /mnt/newdrive
```

Файлы на диске при этом сохраняются, но точка монтирования восстанавливается только после повторного выполнения команды.

## Автоматическое монтирование — файл `/etc/fstab`

Чтобы диск монтировался автоматически при загрузке системы, необходимо добавить запись о нём в файл `/etc/fstab`.

### Создание резервной копии

Перед редактированием рекомендуется сделать копию файла:

```bash
sudo cp /etc/fstab /etc/fstab.backup
```

### Получение UUID раздела

Для надёжной идентификации раздела используется его **UUID** (Universally Unique Identifier):

```bash
lsblk -f
```

В выводе виден UUID для каждого раздела (например, для `sdb1`).

### Редактирование `/etc/fstab`

```bash
sudo nano /etc/fstab
```

Формат одной строки:

 UUID=<значение>  <точка_монтирования>  <тип_ФС>  <опции>  <dump>  <pass>

**Пример добавленной строки:**

 UUID=12345678-1234-1234-1234-123456789abc /mnt/newdrive ext4 defaults,nofail 0 2

|Поле|Значение|Описание|
|---|---|---|
|1|`UUID=...`|Идентификатор раздела|
|2|`/mnt/newdrive`|Точка монтирования|
|3|`ext4`|Тип файловой системы|
|4|`defaults,nofail`|Опции: `nofail` позволяет системе загружаться даже при ошибках монтирования|
|5|`0`|Dump (резервное копирование) — отключено|
|6|`2`|Порядок проверки fsck (1 — root, 2 — остальные разделы)|


> [!warning] Требует проверки
> `mount -a` реально монтирует файловые системы, а не только проверяет синтаксис, и пропускает записи с `noauto`. Предварительная проверка: `findmnt --verify --verbose`. В systemd после изменения `fstab` выполните `sudo systemctl daemon-reload`. Не размонтируйте используемый или корневой раздел ради упражнения. См. [mount(8)](https://man.archlinux.org/man/mount.8.en) и [findmnt(8)](https://man.archlinux.org/man/findmnt.8.en).

## Проверка конфигурации

После добавления записи необходимо проверить корректность:

1. **Размонтировать диск** (если он был примонтирован):

    ```bash
    sudo umount /mnt/newdrive
    ```

    Проверить: `df -h` — диск должен отсутствовать.

2. **Смонтировать всё по `fstab`**:

    ```bash
    sudo mount -a
    ```

    Ключ `-a` (all) монтирует все файловые системы, указанные в `/etc/fstab`.

3. **Проверить результат**:

    ```bash
    df -h
    ```

    Диск должен появиться в списке.


Если команда `mount -a` не выводит ошибок, а диск не появился, возможно, в записи есть ошибка (например, неверный UUID или путь).

## Симуляция ошибки и восстановление

Если в `/etc/fstab` допущена ошибка (например, удалён один символ в UUID), система всё равно может загрузиться (благодаря опции `nofail`), но диск не примонтируется.

**Порядок исправления:**

1. Отредактировать `/etc/fstab`, исправив ошибку

2. Выполнить `sudo mount -a` для проверки

3. Убедиться, что диск появился в `df -h`


## Итог: автоматическое монтирование

|Действие|Команда|
|---|---|
|Ручное монтирование|`sudo mount /dev/sdb1 /mnt/newdrive`|
|Ручное размонтирование|`sudo umount /mnt/newdrive`|
|Получение UUID|`lsblk -f`|
|Редактирование `fstab`|`sudo nano /etc/fstab`|
|Проверка конфигурации|`sudo mount -a`|
|Перезагрузка системы|`reboot`|

**Ключевые понятия:**

- **`/etc/fstab`** — файл с описанием файловых систем, монтируемых автоматически

- **UUID** — уникальный идентификатор раздела (предпочтительнее использования имени устройства)

- **`nofail`** — опция, позволяющая системе загружаться даже при ошибках монтирования

- **`mount -a`** — команда для проверки корректности записей в `fstab`

## Дополнения и особенности системы

> [!info] Arch Linux
> `mkfs.ext4` поставляется в `e2fsprogs`, а `mount`, `umount` и `findmnt` — в `util-linux`. Выбор ext4 в уроке — пример, а не требование Arch. Не форматируйте существующий раздел только для приведения к примеру. См. [файловые системы Arch](https://wiki.archlinux.org/title/file_systems).
