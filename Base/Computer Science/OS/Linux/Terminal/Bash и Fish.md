## Переменные и подстановка команд

Исходные примеры переменных Bash приведены ниже; программирование оболочки — в [[OS/Linux/Terminal/Bash-скрипты]].

> [!info] Fish
> Fish — отдельный язык, не совместимый с POSIX shell. Для экспорта переменной используется `set -gx`, для удаления — `set -e`. Подстановка команд поддерживает `(команда)` и в современных версиях также `$(команда)`; обратные кавычки Bash не поддерживаются. Результат подстановки делится по переводам строк, а не по пробелам.
>
> | Задача | Bash | Fish |
> |---|---|---|
> | Переменная оболочки | `name=value` | `set name value` |
> | Экспорт дочерним процессам | `export APP_ENV=dev` | `set -gx APP_ENV dev` |
> | Удалить переменную | `unset APP_ENV` | `set -e APP_ENV` |
> | Сохранить вывод команды | `today=$(date +%F)` | `set today (date +%F)` |
> | Код последней команды | `echo $?` | `echo $status` |
>
> Для одной внешней команды подходит `env APP_ENV=dev printenv APP_ENV` в обеих оболочках. Источник: [Fish для пользователей Bash](https://fishshell.com/docs/current/fish_for_bash_users.html).

## Конфигурационные файлы

> [!info] Дополнение: Bash
> Интерактивный Bash без режима login читает `~/.bashrc`. Login Bash читает `/etc/profile`, затем первый доступный из `~/.bash_profile`, `~/.bash_login`, `~/.profile`. Чтение `~/.bashrc` из профиля нужно организовать отдельно, если оно требуется. Источник: [bash(1), INVOCATION](https://man.archlinux.org/man/bash.1.en).

> [!info] Fish
> Пользовательская конфигурация обычно находится в `~/.config/fish/config.fish`, дополнительные фрагменты — в `~/.config/fish/conf.d/*.fish`, системная конфигурация — в `/etc/fish/`. Эти файлы используют синтаксис Fish; `source ~/.bashrc` не является способом перенести настройки Bash. `config.fish` читается и неинтерактивными оболочками; интерактивные настройки ограничивайте условием:
>
> ```fish
> if status is-interactive
>     # Настройки только интерактивной оболочки
> end
> ```
>
> Источник: [конфигурационные файлы Fish](https://fishshell.com/docs/current/language.html#configuration-files).

## Запуск скриптов и выбор оболочки

> [!info] Fish
> Интерактивная оболочка Fish не требует переписывать Bash-скрипты. Скрипт с синтаксисом Bash можно запустить явно:
>
> ```fish
> bash script.sh
> ```
>
> Не запускайте такой скрипт через `fish script.sh` или `source script.sh` в Fish. Для назначения Fish оболочкой входа сначала установите его, проверьте путь и `/etc/shells`; порядок описан в [[OS/Linux/Administration/Пользователи и группы]]. См. [Fish для пользователей Bash](https://fishshell.com/docs/current/fish_for_bash_users.html).

## Переменные окружения

Основные понятия:

```text
env
export
PATH
.bashrc
.bash_profile
.profile
```

### `env`

Показать переменные окружения.

```bash
env
```

### `export`

Создать переменную окружения.

```bash
export APP_ENV=production
```

### `PATH`

Переменная, определяющая каталоги, в которых shell ищет исполняемые файлы.

```bash
echo $PATH
```

### Навыки и практика

#### Нужно понимать

```bash
env
printenv
export
unset
echo "$PATH"
```

Разобраться:

- shell variable vs environment variable;
- `PATH`;
- `.bashrc`;
- `.bash_profile`;
- `.profile`;
- почему сервис, запущенный через systemd, может не видеть переменные твоего интерактивного shell.

#### Практика

- [ ] Создать `APP_ENV=dev`.
- [ ] Передать переменную дочернему процессу.
- [ ] Добавить собственную директорию `~/bin` в `PATH`.
- [ ] Положить туда executable script и запустить его просто по имени.
