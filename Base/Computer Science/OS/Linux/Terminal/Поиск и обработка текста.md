# Поиск и обработка текста

[[OS/Linux/Linux|Карта Linux]] · Источник: Terminal Tools Курс

## Итог

В этом уроке рассмотрена команда `find` для поиска файлов в Linux.

|Ключ / Символ|Назначение|
|---|---|
|`-name`|Поиск по имени с учётом регистра|
|`-iname`|Поиск по имени без учёта регистра|
|`*`|Любая последовательность символов (в кавычках)|
|`?`|Один любой символ (в кавычках)|
|`-maxdepth N`|Ограничение глубины поиска|
|`-size +Nk`|Поиск по размеру (k, M, G)|
|`~`|Домашняя директория текущего пользователя|

**Важные особенности:**

- Расширение файла является частью имени

- Имена файлов чувствительны к регистру

- Шаблоны `*` и `?` необходимо заключать в кавычки

- **`find`** по умолчанию ищет рекурсивно во всех поддиректориях

## Утилита `grep` — поиск по строкам

**`grep`** (global regular expression print) — мощный инструмент для поиска строк по шаблону.

### Базовый синтаксис

```bash
grep pattern file
```

### Основные ключи

|Ключ|Описание|
|---|---|
|`-i`|ignore case — игнорировать регистр|
|`-v`|invert — вывести строки, **не** содержащие шаблон|
|`-o`|print only matching — вывести только совпадающую часть строки|
|`-n`|show line numbers — показать номера строк|
|`-r`|recursive — рекурсивный поиск в директориях|

### Примеры с grep и конвейером

**Подсчёт количества упоминаний слова:**

```bash
cat romeo_poem.txt | grep "Montague" | wc -l
```

Считает, сколько строк содержат слово `Montague`.

**Просмотр строк с упоминанием:**

```bash
cat romeo_poem.txt | grep "Capulet"
```

**Вывод только искомого слова (без всей строки):**

```bash
cat romeo_poem.txt | grep -o "Montague"
```

## Анализ логов с помощью конвейера

Системные логи в Linux хранятся в `/var/log/syslog`.

### Подсчёт строк в логе

```bash
cat /var/log/syslog | wc -l
```

### Поиск по службам

```bash
cat /var/log/syslog | grep ssh          # поиск по ssh
cat /var/log/syslog | grep cron         # поиск по cron
cat /var/log/syslog | grep systemd      # поиск по systemd
```

### Многоступенчатая фильтрация

```bash
cat /var/log/syslog | grep ssh | grep root
```

Сначала выбираются строки с **`ssh`**, затем из них — строки с `root`.

### Сохранение результатов

```bash
cat /var/log/syslog | grep ssh | grep root > ssh_root_entries.txt
```

## Дополнения и особенности системы

> [!info] Arch Linux
> `/var/log/syslog` не является универсальным файлом логов. В Arch журнал systemd читается через `journalctl`; отдельный syslog-демон может быть настроен дополнительно. Примеры для установленного OpenSSH-сервера (`sshd.service`):
>
> ```bash
> journalctl -b                         # текущая загрузка
> journalctl -u sshd -n 100 --no-pager  # последние 100 записей службы
> journalctl -u sshd -f                 # следить за новыми записями
> journalctl -b --no-pager | grep root  # текстовая фильтрация
> ```
>
> Доступные записи зависят от прав; для системного журнала может понадобиться `sudo`. Источники: [ArchWiki: Journal](https://wiki.archlinux.org/title/Systemd/Journal), [journalctl(1)](https://man.archlinux.org/man/journalctl.1.en).

## Поиск файлов по имени и базе

### `find`

Поиск файлов.

```bash
find /var/log -name "*.log"
```

### `locate`

Быстрый поиск файлов по базе.

```bash
locate nginx.conf
```

## Работа с текстом

В roadmap отдельно выделены:

```text
grep
awk
sed
cut
sort
uniq
wc
xargs
```

Они особенно полезны для анализа логов.

### `grep`

Поиск текста.

```bash
grep ERROR app.log
```

Поиск без учёта регистра:

```bash
grep -i error app.log
```

Рекурсивный поиск:

```bash
grep -R "ERROR" /var/log
```

### `awk`

Обработка колонок.

Например:

```bash
ps aux | awk '{print $1, $2, $11}'
```

### `sed`

Потоковый редактор текста.

```bash
sed 's/error/ERROR/g' file.txt
```

### `cut`

Извлечение колонок.

```bash
cut -d: -f1 /etc/passwd
```

### `sort`

Сортировка.

```bash
sort file.txt
```

### `uniq`

Удаление повторяющихся соседних строк.

```bash
sort file.txt | uniq
```

Подсчёт повторений:

```bash
sort file.txt | uniq -c
```

### `wc`

Количество строк, слов и символов.

```bash
wc -l app.log
```

### `xargs`

Передаёт данные как аргументы другой команде.

Пример:

```bash
find . -name "*.log" | xargs grep ERROR
```

### Навыки и практика

DevOps постоянно работает с конфигами и логами.

#### Обязательные инструменты

```bash
grep
awk
sed
cut
sort
uniq
wc
tr
xargs
```

#### Что уметь

- найти строку по шаблону;
- исключить строки;
- считать количество совпадений;
- выбрать колонку;
- сортировать;
- удалять дубликаты;
- заменять текст;
- обрабатывать вывод другой команды.

#### Практика

Скопируй `/etc/passwd` в свою директорию и ответь командами:

- [ ] сколько строк в файле;
- [ ] сколько уникальных shell используется;
- [ ] какие пользователи используют `/bin/bash`;
- [ ] вывести только имена пользователей;
- [ ] отсортировать имена;
- [ ] заменить один текстовый фрагмент через `sed` в копии файла.

##### Лаба по логам

Создай `app.log` примерно такого вида:

```text
2026-09-03T10:00:01 INFO user=42 request=/api/users status=200 duration=31ms
2026-09-03T10:00:03 ERROR user=17 request=/api/orders status=500 duration=814ms
2026-09-03T10:00:04 INFO user=11 request=/health status=200 duration=2ms
```

Научись получать:

- только `ERROR`;
- все ответы `500`;
- количество запросов по каждому status code;
- самые долгие запросы.
