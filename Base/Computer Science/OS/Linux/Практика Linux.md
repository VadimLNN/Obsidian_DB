## Практика: приложение без Docker

Roadmap отдельно подчёркивает:

> никакого Docker — сначала нужно научиться запускать приложение непосредственно в Linux.

Состав приложения:

```text
Frontend
Backend
Database
```

Задача:

```text
создать/взять приложение
        ↓
установить зависимости
        ↓
настроить конфигурацию
        ↓
запустить руками
        ↓
оформить сервисы
        ↓
разобраться со всеми непонятными вещами
```

Это важный этап перед Docker.

## Финальная практика перед Docker

Перед переходом к Docker попробуй выполнить всё на обычной Linux-машине или VM.

### Задача

Поднять:

```text
Frontend
Backend
Database
```

без Docker.

### Что должно получиться

```text
Linux
│
├── frontend
│
├── backend
│   └── systemd unit
│
├── database
│
└── logs
```

### Проверка

Ты должен уметь ответить:

```text
Какой процесс запущен?
Какой у него PID?
Какой порт он слушает?
Где его логи?
Сколько он использует RAM?
Что произойдёт после kill?
Как его перезапустить?
Как включить автозапуск?
Почему сервис не стартует?
Как проверить свободное место?
Как проверить inode?
Как проверить RAM?
Как посмотреть Load Average?
```

Если эти вопросы уже не вызывают ступор — Linux-база для следующего этапа DevOps сформирована.

## Главная практическая работа по Linux

Это обязательный итог этапа.

### Условие

Развернуть приложение **без Docker**.

Архитектура:

```text
Internet / localhost
        |
        v
      Nginx
        |
        v
     Backend
        |
        v
    PostgreSQL
```

Можно взять своё приложение на Go / Node.js / Python.

### Требования

#### Пользователь

- [ ] Приложение работает не от root.

#### Backend

- [ ] Приложение запускается как systemd service.
- [ ] `Restart=on-failure` или аналогичная политика настроена.
- [ ] Логи доступны через journalctl.

#### Nginx

- [ ] Nginx работает как reverse proxy.
- [ ] Backend не торчит напрямую наружу.

#### Конфигурация

- [ ] Конфиг приложения не захардкожен в коде.
- [ ] Используются environment variables или отдельный config.
- [ ] Секреты не лежат в Git.

#### PostgreSQL

- [ ] База установлена и запущена.
- [ ] Создан отдельный DB user.
- [ ] Приложение подключается к БД.

#### Диагностика

Ты должен уметь намеренно создать и починить минимум такие поломки:

- [ ] backend не запускается;
- [ ] порт уже занят;
- [ ] Nginx отдаёт `502 Bad Gateway`;
- [ ] неверные права на файл;
- [ ] приложение не видит env variable;
- [ ] PostgreSQL недоступен;
- [ ] DNS не работает;
- [ ] firewall блокирует порт.

## Итоговый checkpoint

Этап Linux считается закрытым, если ты можешь взять чистую Linux VM и самостоятельно:

1. Создать пользователя.
2. Настроить SSH по ключу.
3. Настроить firewall.
4. Установить приложение.
5. Создать systemd unit.
6. Настроить env/config.
7. Поднять PostgreSQL.
8. Поднять Nginx reverse proxy.
9. Проверить логи.
10. Проверить процессы и порты.
11. Сделать приложение доступным по HTTP.
12. Перезагрузить VM и убедиться, что всё поднялось автоматически.
13. Намеренно сломать один компонент и найти причину без переустановки всей системы.

Если это получается — **переходи к Docker**.
