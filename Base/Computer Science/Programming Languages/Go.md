## 1. Первая программа и инструменты

Минимальная исполняемая программа на Go:

```go
package main

import "fmt"

func main() {
	fmt.Println("Hello, 世界")
}
```

Что здесь происходит:

- `package main` объявляет исполняемый пакет;
- `import "fmt"` подключает пакет форматированного ввода-вывода;
- `func main()` — точка входа;
- `fmt.Println` печатает аргументы и добавляет перевод строки.

Исходники Go обычно имеют расширение `.go`. Код принято форматировать стандартным инструментом:

```bash
gofmt -w main.go
go run main.go
```

Для проекта используется модуль:

```bash
go mod init example.com/myproject
go run .
```

> [!important]
> Форматирование в Go стандартизировано. Не нужно вручную спорить о пробелах и расположении фигурных скобок: запускается `gofmt`.

### Go Playground

Встроенная площадка тура компилирует и запускает код удалённо. У неё есть ограничения:

- выполнение изолировано;
- время моделируется особым образом;
- доступ к сети и файловой системе ограничен;
- результат одного и того же кода должен быть воспроизводимым.

## 2. Пакеты, импорты и экспорт

### Пакеты

Каждый `.go`-файл начинается с объявления пакета:

```go
package main
```

Программа состоит из пакетов. Запуск исполняемой программы начинается с пакета `main` и функции `main`.

Имя пакета обычно совпадает с последней частью пути импорта:

```go
import "math/rand" // обращаться будем как rand
```

### Импорты

Один импорт:

```go
import "fmt"
```

Несколько импортов принято объединять:

```go
import (
	"fmt"
	"math"
)
```

Неиспользуемый импорт — ошибка компиляции. Это сохраняет код чистым и не позволяет зависимостям накапливаться незаметно.

### Экспортируемые имена

Имя доступно из другого пакета, если начинается с заглавной буквы:

```go
math.Pi     // экспортируется
fmt.Println // экспортируется
```

Имя с маленькой буквы видно только внутри своего пакета:

```go
var internalValue = 10
```

> [!tip]
> В Go регистр первой буквы — часть системы видимости: `User` экспортируется, `user` — нет.

## 3. Функции

### Объявление

Тип указывается после имени параметра:

```go
func add(x int, y int) int {
	return x + y
}
```

Одинаковые соседние типы можно сократить:

```go
func add(x, y int) int {
	return x + y
}
```

Общая форма:

```go
func имя(параметры) возвращаемыеТипы {
	// тело
}
```

### Несколько возвращаемых значений

Функция может вернуть несколько результатов:

```go
func swap(x, y string) (string, string) {
	return y, x
}

func main() {
	a, b := swap("hello", "world")
	fmt.Println(a, b)
}
```

Это часто используется для возврата результата и ошибки:

```go
value, err := doSomething()
```

Если одно значение не нужно, применяется пустой идентификатор `_`:

```go
value, _ := strconv.Atoi("42")
```

Игнорировать ошибки через `_` без причины — плохая практика.

### Именованные результаты

Возвращаемым значениям можно дать имена:

```go
func split(sum int) (x, y int) {
	x = sum * 4 / 9
	y = sum - x
	return
}
```

`return` без аргументов возвращает текущие значения `x` и `y`. Это называется **naked return**.

> [!warning]
> Именованные результаты полезны для документации короткой функции, но в длинной функции «голый» `return` ухудшает читаемость.

## 4. Переменные, типы и константы

### `var`

`var` объявляет переменную. Тип пишется после имени:

```go
var count int
var active bool
```

Объявления можно объединить:

```go
var (
	name string
	age  int
)
```

### Инициализация и вывод типа

Если есть начальное значение, компилятор может вывести тип:

```go
var i, j int = 1, 2
var language = "Go" // string
```

Короткое объявление доступно только внутри функций:

```go
k := 3
name := "Gopher"
```

Эквивалент:

```go
var k = 3
```

> [!important]
> `:=` объявляет хотя бы одну новую переменную. Для присваивания уже объявленной переменной используется `=`.

```go
x := 1 // объявление
x = 2  // присваивание
```

Допустимо переиспользовать часть имён, если хотя бы одно имя новое:

```go
x := 1
x, y := 2, 3 // y новая, поэтому := допустим
```

### Базовые типы

| Группа | Типы | Назначение |
|---|---|---|
| Логический | `bool` | `true` или `false` |
| Строковый | `string` | неизменяемая последовательность байтов |
| Знаковые целые | `int`, `int8`, `int16`, `int32`, `int64` | целые числа |
| Беззнаковые целые | `uint`, `uint8`, `uint16`, `uint32`, `uint64`, `uintptr` | неотрицательные целые |
| Байтовый псевдоним | `byte` | псевдоним `uint8` |
| Unicode-псевдоним | `rune` | псевдоним `int32`, кодовая точка Unicode |
| Дробные | `float32`, `float64` | числа с плавающей точкой |
| Комплексные | `complex64`, `complex128` | комплексные числа |

Обычно для целых чисел используют `int`, а для дробных — `float64`, если нет конкретной причины выбрать другой размер.

Размер `int`, `uint` и `uintptr` зависит от архитектуры: обычно 32 бита на 32-битной системе и 64 бита на 64-битной.

### Нулевые значения

Неинициализированная переменная получает **zero value**:

| Тип | Нулевое значение |
|---|---|
| числа | `0` |
| `bool` | `false` |
| `string` | `""` |
| указатели, срезы, карты, функции, интерфейсы, каналы | `nil` |

```go
var i int       // 0
var ok bool     // false
var text string // ""
```

В Go нет неинициализированного «мусора»: значение всегда определено.

### Преобразование типов

Неявных числовых преобразований почти нет:

```go
var x, y int = 3, 4
var f float64 = math.Sqrt(float64(x*x + y*y))
var z uint = uint(f)
```

Общая форма:

```go
T(value)
```

Это помогает не скрывать потерю точности или изменение знака.

### Вывод типа

Тип переменной без явного типа определяется по правой части:

```go
i := 42           // int
f := 3.142        // float64
g := 0.867 + 0.5i // complex128
```

Если справа находится уже типизированная переменная, новая переменная получает тот же тип.

### Константы

Константа объявляется через `const` и не может использовать `:=`:

```go
const Pi = 3.14
const World = "世界"
```

Константы бывают символьными, строковыми, логическими и числовыми.

Числовая константа может хранить значение высокой точности и получает конкретный тип только тогда, когда этого требует контекст:

```go
const Big = 1 << 100
const Small = Big >> 99

fmt.Println(needInt(Small))
fmt.Println(needFloat(Small))
```

> [!note]
> Нетипизированная константа гибче переменной: компилятор подбирает подходящий тип, если значение в него помещается.

## 5. Управление потоком выполнения

### Цикл `for`

В Go есть один ключевой цикл — `for`:

```go
sum := 0
for i := 0; i < 10; i++ {
	sum += i
}
```

Круглые скобки вокруг условия не нужны, фигурные обязательны.

Инициализация и завершающая инструкция необязательны:

```go
sum := 1
for sum < 1000 {
	sum += sum
}
```

Так `for` заменяет `while`.

Бесконечный цикл:

```go
for {
	// выполняется, пока не встретится break, return или panic
}
```

Полезные операторы:

- `break` — выйти из ближайшего цикла или `switch`;
- `continue` — перейти к следующей итерации.

### Упражнение тура: квадратный корень методом Ньютона

Тур предлагает приблизить $\sqrt{x}$ последовательным уточнением значения `z`:

$$
z \leftarrow z - \frac{z^2-x}{2z}
$$

Практическая форма:

```go
func Sqrt(x float64) float64 {
	z := 1.0
	for {
		previous := z
		z -= (z*z - x) / (2 * z)
		if math.Abs(z-previous) < 1e-12 {
			return z
		}
	}
}
```

Смысл упражнения — потренировать цикл, условие и численное приближение. Сравнивать `float64` через точное `==` обычно ненадёжно: лучше остановиться, когда изменение стало меньше выбранной погрешности.

### `if`

```go
if x < 0 {
	return -x
}
```

Перед условием можно выполнить короткую инструкцию:

```go
if value := math.Pow(x, n); value < limit {
	return value
}
```

`value` доступна внутри `if` и связанного `else`, но не после них:

```go
if value := math.Pow(x, n); value < limit {
	return value
} else {
	fmt.Printf("%g >= %g\n", value, limit)
}
```

Этот приём особенно часто встречается при обработке ошибок:

```go
if err := validate(); err != nil {
	return err
}
```

### `switch`

```go
switch os := runtime.GOOS; os {
case "darwin":
	fmt.Println("macOS")
case "linux":
	fmt.Println("Linux")
default:
	fmt.Printf("%s\n", os)
}
```

Особенности:

- выражение вычисляется один раз;
- выполнение идёт только по первой подходящей ветке;
- автоматического перехода в следующую ветку нет;
- явный `break` обычно не нужен;
- случаи проверяются сверху вниз;
- выражения `case` не обязаны быть константами.

Выражения `case` вычисляются только по мере проверки сверху вниз. После первого совпадения остальные случаи не вычисляются. Это позволяет безопасно располагать более дешёвые или более вероятные проверки раньше.

Чтобы явно продолжить следующую ветку, существует `fallthrough`, но он применяется редко.

`switch` без выражения эквивалентен `switch true` и заменяет длинную цепочку `if-else`:

```go
switch {
case hour < 12:
	fmt.Println("Доброе утро")
case hour < 18:
	fmt.Println("Добрый день")
default:
	fmt.Println("Добрый вечер")
}
```

### `defer`

`defer` откладывает вызов функции до завершения окружающей функции:

```go
func work() {
	defer fmt.Println("готово")
	fmt.Println("работа")
}
```

Вывод:

```text
работа
готово
```

Аргументы отложенного вызова вычисляются сразу, а сам вызов выполняется позже:

```go
x := 1
defer fmt.Println(x) // запомнит 1
x = 2
```

Несколько `defer` выполняются как стек — **LIFO**, последним добавлен, первым выполнен:

```go
for i := 0; i < 3; i++ {
	defer fmt.Println(i)
}
// 2, 1, 0
```

Главное применение — освобождение ресурса рядом с его получением:

```go
file, err := os.Open("data.txt")
if err != nil {
	return err
}
defer file.Close()
```

> [!warning]
> `defer` привязан к функции, а не к блоку. Если ставить его внутри очень длинного цикла, ресурсы могут освободиться только при выходе из всей функции.

## 6. Указатели и структуры

### Указатели

Указатель хранит адрес значения:

```go
var p *int
```

- `&x` — получить адрес `x`;
- `*p` — прочитать или изменить значение по адресу `p`.

```go
i := 42
p := &i
fmt.Println(*p) // 42
*p = 21
fmt.Println(i)  // 21
```

Нулевое значение указателя — `nil`.

> [!note]
> В Go нет арифметики указателей, привычной по C. Нельзя прибавить к указателю число и перейти к произвольной области памяти.

Передача указателя позволяет функции изменить исходное значение:

```go
func scale(v *int) {
	*v *= 2
}
```

### Структуры

Структура объединяет поля:

```go
type Vertex struct {
	X int
	Y int
}
```

Создание и доступ:

```go
v := Vertex{X: 1, Y: 2}
fmt.Println(v.X)
v.X = 10
```

Через указатель к полю можно обращаться без явного разыменования:

```go
p := &v
p.X = 20 // сокращение для (*p).X = 20
```

### Литералы структур

```go
v1 := Vertex{1, 2}       // по порядку полей
v2 := Vertex{X: 1}       // Y получит 0
v3 := Vertex{}           // X и Y равны 0
p := &Vertex{X: 1, Y: 2} // *Vertex
```

Предпочтительнее указывать имена полей: такой код легче читать и безопаснее изменять.

## 7. Массивы и срезы

### Массивы

Тип массива включает длину:

```go
var a [2]string
a[0] = "Hello"
a[1] = "World"
```

`[2]int` и `[3]int` — разные типы. Размер массива фиксирован.

Литерал:

```go
primes := [6]int{2, 3, 5, 7, 11, 13}
```

Массив при обычном присваивании или передаче в функцию копируется целиком.

### Срезы

Срез `[]T` — гибкое представление последовательности элементов массива:

```go
var s []int = primes[1:4]
```

Диапазон полуоткрытый: нижняя граница включается, верхняя — нет.

```go
a[low:high]
```

`a[1:4]` содержит элементы с индексами `1`, `2`, `3`.

Срез не хранит элементы самостоятельно. Упрощённо он содержит:

1. указатель на базовый массив;
2. длину;
3. ёмкость.

Поэтому изменение элемента среза меняет общий базовый массив и видно другим срезам:

```go
names := [4]string{"John", "Paul", "George", "Ringo"}
a := names[0:2]
b := names[1:3]
b[0] = "XXX"

fmt.Println(a)     // [John XXX]
fmt.Println(names) // [John XXX George Ringo]
```

### Литералы срезов

```go
numbers := []int{2, 3, 5, 7}
points := []struct {
	X int
	Y int
}{
	{2, 3},
	{5, 7},
}
```

Литерал среза создаёт массив, а затем срез, который на него ссылается.

### Границы по умолчанию

Для массива или среза длины `n`:

```go
a[0:n]
a[:n]
a[0:]
a[:]
```

Эти формы могут обозначать один диапазон.

### Длина и ёмкость

- `len(s)` — число элементов, доступных через срез;
- `cap(s)` — число элементов от начала среза до конца базового массива.

```go
s := []int{2, 3, 5, 7, 11, 13}
s = s[:0] // len=0, данные всё ещё находятся в базовом массиве
s = s[:4] // увеличить длину в пределах cap
s = s[2:] // отбросить первые два элемента
```

Выход за пределы допустимой длины или ёмкости приводит к panic.

### Нулевой срез

```go
var s []int
```

У него:

- `s == nil`;
- `len(s) == 0`;
- `cap(s) == 0`.

По нулевому срезу можно безопасно делать `range` и к нему можно применять `append`.

### `make`

`make` создаёт срез заданной длины и, при необходимости, ёмкости:

```go
a := make([]int, 5)     // len=5, cap=5
b := make([]int, 0, 5)  // len=0, cap=5
c := make([]int, 5, 10) // len=5, cap=10
```

`make` применяется к срезам, картам и каналам. `new(T)` лишь выделяет память под нулевое значение `T` и возвращает `*T`; это другая операция.

### Срезы срезов

Срез может содержать другие срезы. Так можно представить таблицу или изображение:

```go
board := [][]string{
	{"_", "_", "_"},
	{"_", "_", "_"},
	{"_", "_", "_"},
}
```

Строки могут иметь разную длину: `[][]T` не обязан быть прямоугольной матрицей.

### `append`

```go
var s []int
s = append(s, 1)
s = append(s, 2, 3, 4)
```

Сигнатура по смыслу:

```go
func append(s []T, values ...T) []T
```

Результат нужно присвоить обратно. Если ёмкости не хватает, `append` создаёт новый базовый массив и возвращает срез на него.

```go
s = append(s, value) // правильно
```

Добавление другого среза:

```go
s = append(s, other...)
```

> [!warning]
> До перераспределения памяти два среза могут разделять массив, а после `append` — уже нет. Нельзя бездумно полагаться на общность их данных.

### `range`

`range` перебирает элементы среза или массива и возвращает индекс и копию значения:

```go
for i, value := range numbers {
	fmt.Println(i, value)
}
```

Если индекс не нужен:

```go
for _, value := range numbers {
	fmt.Println(value)
}
```

Если значение не нужно:

```go
for i := range numbers {
	fmt.Println(i)
}
```

Для изменения элемента надёжно обращаться по индексу:

```go
for i := range numbers {
	numbers[i] *= 2
}
```

Переменная `value` обычно содержит копию элемента, поэтому изменение `value` не изменяет элемент среза.

### Упражнение тура: изображение

Тур предлагает вернуть `[][]uint8`, где каждый элемент — интенсивность пикселя. Полезные идеи:

- внешний срез — строки изображения;
- внутренний срез — пиксели строки;
- каждый внутренний срез нужно создать отдельно;
- значение можно вычислять из координат `x` и `y`.

## 8. Словари `map`

`map[K]V` связывает ключи типа `K` со значениями типа `V`:

```go
var users map[string]int
```

Нулевая карта равна `nil`. Читать из неё можно, записывать — нельзя.

Создание:

```go
users := make(map[string]int)
users["Alice"] = 30
```

Литерал:

```go
type Vertex struct {
	Lat, Long float64
}

locations := map[string]Vertex{
	"Bell Labs": {40.68433, -74.39967},
	"Google":    {37.42202, -122.08408},
}
```

Если тип значения уже указан как `Vertex`, его имя внутри литерала можно не повторять.

### Изменение карты

```go
m[key] = value      // добавить или заменить
value := m[key]     // получить
delete(m, key)      // удалить
value, ok := m[key] // проверить наличие
```

`ok == true`, если ключ присутствует.

```go
value, ok := users["Bob"]
if !ok {
	fmt.Println("ключа нет")
}
```

Если ключа нет, чтение возвращает нулевое значение типа `V`. Поэтому без `ok` нельзя отличить «ключ отсутствует» от «ключ существует и хранит ноль».

Перебор:

```go
for key, value := range users {
	fmt.Println(key, value)
}
```

> [!warning]
> Порядок обхода `map` не определён. Нельзя рассчитывать на порядок вставки или сортировку.

Ключ должен быть сравнимым типом. Например, строки, числа, указатели и многие структуры подходят, а срезы и карты — нет.

### Упражнение тура: подсчёт слов

Типичная схема:

```go
func WordCount(s string) map[string]int {
	counts := make(map[string]int)
	for _, word := range strings.Fields(s) {
		counts[word]++
	}
	return counts
}
```

Здесь удобно то, что отсутствующий ключ возвращает `0`, поэтому предварительно создавать каждый счётчик не нужно.

## 9. Функции как значения и замыкания

### Функция — значение

Функцию можно сохранить в переменную, передать аргументом и вернуть из другой функции:

```go
hypot := func(x, y float64) float64 {
	return math.Sqrt(x*x + y*y)
}

fmt.Println(hypot(3, 4))
```

Функция высшего порядка:

```go
func compute(fn func(float64, float64) float64) float64 {
	return fn(3, 4)
}
```

### Замыкание

Замыкание — функция, которая использует переменные из внешней области видимости и сохраняет связь с ними:

```go
func adder() func(int) int {
	sum := 0
	return func(x int) int {
		sum += x
		return sum
	}
}
```

Каждый вызов `adder()` создаёт независимую переменную `sum`:

```go
pos, neg := adder(), adder()
fmt.Println(pos(1))  // 1
fmt.Println(pos(2))  // 3
fmt.Println(neg(-1)) // -1
```

Замыкания полезны для:

- накопления состояния;
- конфигурации обработчиков;
- создания функций-фабрик;
- колбэков;
- инкапсуляции небольшого состояния.

### Упражнение тура: Fibonacci closure

Нужно вернуть функцию, которая при каждом вызове выдаёт следующее число Фибоначчи. Состояние можно хранить в двух захваченных переменных:

```go
func fibonacci() func() int {
	a, b := 0, 1
	return func() int {
		result := a
		a, b = b, a+b
		return result
	}
}
```

## 10. Методы

В Go нет классов, но можно объявлять методы у типов.

### Получатель метода

Метод — функция со специальным аргументом-получателем (**receiver**):

```go
type Vertex struct {
	X, Y float64
}

func (v Vertex) Abs() float64 {
	return math.Sqrt(v.X*v.X + v.Y*v.Y)
}
```

Вызов:

```go
v := Vertex{3, 4}
fmt.Println(v.Abs()) // 5
```

Получатель располагается между `func` и именем метода:

```go
func (receiver ReceiverType) MethodName(parameters) results
```

Метод можно объявить не только для структуры, но и для любого именованного типа, определённого в том же пакете:

```go
type MyFloat float64

func (f MyFloat) Abs() float64 {
	if f < 0 {
		return float64(-f)
	}
	return float64(f)
}
```

Нельзя добавлять методы к типу из другого пакета или к встроенному типу напрямую. Сначала нужен собственный именованный тип.

### Метод как обычная функция

```go
func (v Vertex) Abs() float64 { /* ... */ }
```

можно воспринимать как функцию:

```go
func Abs(v Vertex) float64 { /* ... */ }
```

И вызывать через **method expression**:

```go
f := Vertex.Abs
fmt.Println(f(v))
```

### Получатель-значение

```go
func (v Vertex) Scale(f float64) {
	v.X *= f
	v.Y *= f
}
```

`v` — копия. Изменения полей не изменят исходный `Vertex`.

### Получатель-указатель

```go
func (v *Vertex) Scale(f float64) {
	v.X *= f
	v.Y *= f
}
```

Теперь метод изменяет исходное значение.

Go автоматически берёт адрес при удобном вызове:

```go
v := Vertex{3, 4}
v.Scale(10) // компилятор воспринимает как (&v).Scale(10)
```

А для метода с получателем-значением Go может автоматически разыменовать указатель:

```go
p := &v
fmt.Println(p.Abs()) // воспринимается как (*p).Abs()
```

Для обычных функций такой автоматической адаптации нет:

```go
func Scale(v *Vertex, f float64) { /* ... */ }

Scale(&v, 10) // нужен явный адрес
```

### Как выбрать тип получателя

Указатель `*T` выбирают, если:

- метод должен изменять значение;
- структура большая и копировать её дорого;
- нужно сохранять единый набор методов и семантику.

Значение `T` подходит, если:

- тип маленький и неизменяемый по смыслу;
- метод только читает данные;
- копирование ожидаемо, например у небольшого числового типа.

> [!tip]
> Для одного типа обычно придерживаются единого стиля получателей. Если хотя бы часть методов требует `*T`, остальные часто тоже делают с `*T`.

### Наборы методов

Это важно для интерфейсов:

- набор методов `T` содержит методы с получателем `T`;
- набор методов `*T` содержит методы с получателем `T` и `*T`.

Следствие: если требуемый метод объявлен только на `*T`, значение `T` интерфейс не реализует, а `*T` реализует.

## 11. Интерфейсы

### Определение

Интерфейс задаёт набор сигнатур методов:

```go
type Abser interface {
	Abs() float64
}
```

Значение интерфейсного типа может хранить значение любого типа, у которого есть все требуемые методы.

```go
var a Abser
a = MyFloat(-math.Sqrt2)
a = &Vertex{3, 4}
```

### Неявная реализация

В Go нет ключевого слова `implements`. Тип реализует интерфейс автоматически, если имеет нужный набор методов:

```go
type I interface {
	M()
}

type T struct {
	S string
}

func (t T) M() {
	fmt.Println(t.S)
}

var i I = T{S: "hello"}
```

Преимущества:

- реализация не зависит от интерфейса;
- интерфейс можно объявить рядом с потребителем;
- проще разделять пакеты и подменять зависимости в тестах.

Обычно хорошие Go-интерфейсы маленькие. Часто достаточно одного-двух методов.

### Что хранится внутри интерфейса

Упрощённая модель интерфейсного значения:

```text
(конкретное значение, конкретный тип)
```

```go
var i I
i = &T{S: "Hello"}
```

Внутри `i` находятся конкретный тип `*T` и указатель на конкретное значение. При `i.M()` вызывается реализация `M` у `*T`.

### `nil` внутри интерфейса

Возможны два разных состояния.

#### Интерфейс содержит типизированный `nil`

```go
var t *T
var i I = t
```

Состояние интерфейса:

```text
(nil, *T)
```

Поэтому:

```go
i != nil
```

Метод можно вызвать, но реализация должна уметь работать с `nil`-получателем, иначе возможна panic.

#### Нулевой интерфейс

```go
var i I
```

Состояние:

```text
(nil, nil)
```

Здесь `i == nil`. Вызов метода невозможен, потому что неизвестен конкретный тип и его реализация.

> [!warning] Частая ошибка
> Интерфейс равен `nil` только тогда, когда внутри нет ни значения, ни конкретного типа. Интерфейс с типизированным `nil` не равен `nil`.

### Пустой интерфейс и `any`

Интерфейс без методов принимает значение любого типа:

```go
interface{}
```

Современное имя-псевдоним:

```go
any
```

```go
var value any
value = 42
value = "hello"
```

`any` полезен на границах универсального кода, но внутри прикладной логики конкретные типы дают больше безопасности. Использование `any` не отменяет проверку типа.

### Утверждение типа

Type assertion извлекает конкретное значение из интерфейса:

```go
s := value.(string)
```

Если внутри не `string`, программа завершится panic.

Безопасная форма:

```go
s, ok := value.(string)
if !ok {
	fmt.Println("это не строка")
}
```

При успехе `s` содержит строку и `ok == true`. При неудаче `s` получает нулевое значение `string`, а `ok == false`.

### Переключатель типов

```go
func describe(value any) {
	switch v := value.(type) {
	case int:
		fmt.Printf("int: %d\n", v)
	case string:
		fmt.Printf("string: %q\n", v)
	default:
		fmt.Printf("unknown: %T\n", v)
	}
}
```

`value.(type)` разрешено только внутри `type switch`.

## 12. Стандартные интерфейсы

### `fmt.Stringer`

```go
type Stringer interface {
	String() string
}
```

Тип с методом `String() string` умеет представить себя строкой. Пакет `fmt` использует этот интерфейс при печати:

```go
type IPAddr [4]byte

func (ip IPAddr) String() string {
	return fmt.Sprintf("%d.%d.%d.%d", ip[0], ip[1], ip[2], ip[3])
}
```

> [!warning]
> Внутри `String()` нельзя бездумно форматировать тот же объект через `%v`, если это снова вызывает `String()`: получится рекурсия.

### `error`

Встроенный интерфейс ошибок:

```go
type error interface {
	Error() string
}
```

Обычный шаблон:

```go
result, err := operation()
if err != nil {
	return err
}
```

Собственный тип ошибки:

```go
type MyError struct {
	When time.Time
	What string
}

func (e *MyError) Error() string {
	return fmt.Sprintf("at %v, %s", e.When, e.What)
}
```

Ошибки — обычные значения. Их можно создавать, возвращать, оборачивать и проверять.

Создание простой ошибки:

```go
err := errors.New("что-то пошло не так")
```

Форматированная ошибка:

```go
err := fmt.Errorf("read %s: %w", path, cause)
```

`%w` сохраняет исходную ошибку в цепочке. Для проверки применяются `errors.Is` и `errors.As`.

### Упражнение тура: ошибка в `Sqrt`

Вместо специального числового результата функция может вернуть пару `(float64, error)`:

```go
func Sqrt(x float64) (float64, error) {
	if x < 0 {
		return 0, ErrNegativeSqrt(x)
	}
	// вычисление корня
}
```

Главная идея: не прятать ошибочное состояние внутри обычного результата.

### `io.Reader`

```go
type Reader interface {
	Read(p []byte) (n int, err error)
}
```

`Read` записывает данные в переданный буфер `p` и сообщает:

- `n` — сколько байтов прочитано;
- `err` — что произошло, например `io.EOF` при завершении потока.

```go
buffer := make([]byte, 8)
for {
	n, err := reader.Read(buffer)
	fmt.Printf("n=%d data=%q\n", n, buffer[:n])
	if err == io.EOF {
		break
	}
	if err != nil {
		return err
	}
}
```

Важно обрабатывать `n` даже когда `err != nil`: реализация имеет право одновременно вернуть последние данные и `io.EOF`.

Многие типы стандартной библиотеки реализуют `io.Reader`: файлы, сетевые соединения, буферы, строки через `strings.Reader`.

### Упражнение `rot13Reader`

Декоратор-читатель хранит другой `io.Reader`, читает из него и преобразует полученные байты:

```go
type rot13Reader struct {
	r io.Reader
}

func (r rot13Reader) Read(p []byte) (int, error) {
	n, err := r.r.Read(p)
	for i := 0; i < n; i++ {
		p[i] = rotate(p[i])
	}
	return n, err
}
```

Это пример композиции: новый тип расширяет поведение существующего интерфейса.

### `image.Image`

Упрощённо интерфейс выглядит так:

```go
type Image interface {
	ColorModel() color.Model
	Bounds() Rectangle
	At(x, y int) color.Color
}
```

Чтобы собственный тип стал изображением, достаточно реализовать эти методы. Снова не требуется явное `implements`.

В упражнении тура обычно:

- `Bounds()` возвращает прямоугольник изображения;
- `ColorModel()` возвращает цветовую модель;
- `At(x, y)` вычисляет цвет пикселя по координатам.

## 13. Дженерики

Дженерики позволяют писать функции и типы, работающие с набором типов, сохраняя статическую проверку.

### Параметры типа

```go
func Index[T comparable](items []T, target T) int {
	for i, value := range items {
		if value == target {
			return i
		}
	}
	return -1
}
```

Разбор:

- `[T comparable]` объявляет параметр типа `T`;
- `comparable` — ограничение;
- `[]T` и `target T` используют выбранный конкретный тип;
- ограничение разрешает `==` и `!=`.

Вызов:

```go
Index([]int{10, 20, 30}, 20)
Index([]string{"a", "b"}, "b")
```

Компилятор обычно выводит `T`, поэтому писать `Index[int](...)` не нужно.

### Ограничения

Ограничение — интерфейс, описывающий допустимые типы и операции.

```go
type Number interface {
	~int | ~int64 | ~float64
}

func Sum[T Number](values []T) T {
	var total T
	for _, value := range values {
		total += value
	}
	return total
}
```

- `|` означает объединение допустимых типов;
- `~int` включает `int` и именованные типы с базовым типом `int`;
- разрешённые операции определяются ограничением.

`any` означает отсутствие специальных требований:

```go
func First[T any](values []T) T {
	return values[0]
}
```

### Обобщённые типы

Параметры типа можно использовать в структурах:

```go
type List[T any] struct {
	next *List[T]
	val  T
}
```

Использование:

```go
ints := List[int]{val: 1}
words := List[string]{val: "Go"}
```

### Когда дженерики полезны

- один алгоритм действительно одинаков для нескольких типов;
- контейнер должен хранить значения разных конкретных типов без `any`;
- требуется сохранить проверку типов на этапе компиляции.

Не стоит применять дженерики, если обычный конкретный тип или маленький поведенческий интерфейс выражает задачу проще.

> [!tip]
> Интерфейс отвечает на вопрос «какое поведение нужно?», а параметр типа — «для какого множества типов один и тот же алгоритм должен сохранить конкретный тип?»

## 14. Конкурентность

### Конкурентность и параллелизм

- **Конкурентность** — организация нескольких независимо продвигающихся задач.
- **Параллелизм** — физическое выполнение задач одновременно на нескольких вычислителях.

Go даёт языковые средства конкурентности. Будет ли выполнение параллельным, зависит от среды и планировщика.

### Горутины

Горутина — лёгкий конкурентный поток выполнения, управляемый рантаймом Go:

```go
go f(x, y)
```

Вычисление `f`, `x` и `y` происходит в текущей горутине, а выполнение `f` начинается в новой.

```go
func say(text string) {
	for i := 0; i < 5; i++ {
		time.Sleep(100 * time.Millisecond)
		fmt.Println(text)
	}
}

func main() {
	go say("world")
	say("hello")
}
```

Порядок вывода конкурентных задач нельзя считать фиксированным.

> [!warning]
> Завершение `main` завершает всю программу, даже если другие горутины ещё работают. Ожидание нужно организовать явно — например, через канал или `sync.WaitGroup`.

### Каналы

Канал — типизированный механизм передачи значений между горутинами:

```go
ch := make(chan int)
```

Отправка и получение:

```go
ch <- value // отправить
value := <-ch // получить
```

По умолчанию небуферизованный канал синхронизирует стороны:

- отправитель ждёт получателя;
- получатель ждёт отправителя;
- после встречи значение передаётся.

Пример разделения работы:

```go
func sum(values []int, ch chan int) {
	total := 0
	for _, value := range values {
		total += value
	}
	ch <- total
}

func main() {
	values := []int{7, 2, 8, -9, 4, 0}
	ch := make(chan int)

	go sum(values[:len(values)/2], ch)
	go sum(values[len(values)/2:], ch)

	x, y := <-ch, <-ch
	fmt.Println(x, y, x+y)
}
```

### Направленные каналы

Сигнатура может ограничить направление:

```go
func producer(out chan<- int) { // только отправка
	out <- 42
}

func consumer(in <-chan int) { // только получение
	fmt.Println(<-in)
}
```

Это документирует контракт и позволяет компилятору обнаружить неправильную операцию.

### Буферизированные каналы

```go
ch := make(chan int, 2)
```

Отправка блокируется только при полном буфере. Получение блокируется при пустом буфере.

```go
ch <- 1
ch <- 2
fmt.Println(<-ch)
fmt.Println(<-ch)
```

Если попытаться отправить третье значение без параллельного чтения, возникнет блокировка.

> [!important]
> Буфер не является универсальным исправлением взаимной блокировки. Размер буфера должен вытекать из протокола обмена, а не маскировать отсутствие получателя.

### Закрытие канала и `range`

Отправитель может сообщить, что новых значений не будет:

```go
close(ch)
```

Получатель проверяет состояние:

```go
value, ok := <-ch
```

- `ok == true` — получено отправленное значение;
- `ok == false` — канал закрыт и опустошён.

Перебор до закрытия:

```go
for value := range ch {
	fmt.Println(value)
}
```

Правила:

- закрывает обычно отправитель;
- отправка в закрытый канал вызывает panic;
- повторное закрытие вызывает panic;
- получать из закрытого и опустошённого канала можно: сразу вернётся нулевое значение и `ok == false`;
- закрывать канал нужно не всегда, а когда получателю важно узнать о конце потока.

> [!warning]
> Не закрывайте канал со стороны получателя: он не знает, закончили ли все отправители.

### `select`

`select` ждёт несколько операций с каналами:

```go
select {
case value := <-ch1:
	fmt.Println("ch1:", value)
case ch2 <- result:
	fmt.Println("sent:", result)
}
```

Поведение:

- блокируется, пока не готов хотя бы один `case`;
- если готовы несколько, выбирает один псевдослучайно;
- позволяет строить таймауты, отмену и объединение потоков.

Пример с таймаутом:

```go
select {
case result := <-results:
	fmt.Println(result)
case <-time.After(2 * time.Second):
	fmt.Println("timeout")
}
```

В реальном серверном коде отмену обычно передают через `context.Context`.

### `default` в `select`

`default` выполняется, если ни одна операция с каналом сейчас не готова:

```go
select {
case value := <-ch:
	fmt.Println(value)
default:
	fmt.Println("данных пока нет")
}
```

Так получается неблокирующая операция. Но цикл с постоянно срабатывающим `default` может бессмысленно загружать CPU.

### Упражнение: эквивалентные бинарные деревья

Идея решения:

1. Функция `Walk` обходит дерево по порядку **left → node → right**.
2. Каждое значение отправляется в канал.
3. После полного обхода канал закрывается.
4. `Same` запускает два обхода параллельно и сравнивает последовательности.

Почему это работает: для дерева поиска симметричный обход выдаёт значения по возрастанию. Разная форма деревьев не мешает сравнению их содержимого.

Схема обхода:

```go
func Walk(t *tree.Tree, ch chan int) {
	if t == nil {
		return
	}
	Walk(t.Left, ch)
	ch <- t.Value
	Walk(t.Right, ch)
}
```

Закрывать канал удобно в отдельной запускающей горутине:

```go
go func() {
	Walk(t, ch)
	close(ch)
}()
```

### `sync.Mutex`

Если несколько горутин обращаются к общей памяти, операции нужно синхронизировать.

```go
type SafeCounter struct {
	mu sync.Mutex
	v  map[string]int
}

func (c *SafeCounter) Inc(key string) {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.v[key]++
}

func (c *SafeCounter) Value(key string) int {
	c.mu.Lock()
	defer c.mu.Unlock()
	return c.v[key]
}
```

`Lock` захватывает мьютекс, `Unlock` освобождает. Пока мьютекс занят, другая горутина на `Lock` ждёт.

Почему блокировка нужна и для чтения: обычная `map` небезопасна при одновременной записи и чтении.

> [!important]
> Защищайте одним мьютексом конкретный инвариант или группу связанных полей. Критическую секцию делайте короткой и не копируйте структуру, содержащую используемый `sync.Mutex`.

Для преимущественно читаемых данных существует `sync.RWMutex`, но начинать обычно проще с `sync.Mutex`.

### Канал или мьютекс

| Ситуация | Обычно подходит |
|---|---|
| Передать работу или результат между горутинами | канал |
| Сообщить о событии или завершении | канал |
| Защитить короткий доступ к общему состоянию | мьютекс |
| Владелец состояния — одна горутина, остальные отправляют ей команды | канал |
| Простой счётчик или карта с конкурентным доступом | мьютекс |

Это не взаимоисключающие инструменты. В одной программе могут быть и каналы, и мьютексы.

### Упражнение: конкурентный веб-краулер

Задача демонстрирует несколько проблем:

- ссылки можно обходить параллельно;
- одну страницу нельзя загружать повторно;
- множество посещённых URL — общее состояние;
- перед завершением нужно дождаться дочерних задач.

Один из простых подходов:

1. защитить `visited map[string]bool` мьютексом;
2. атомарно проверить и отметить URL перед запуском загрузки;
3. использовать `sync.WaitGroup` для ожидания всех горутин;
4. не держать мьютекс во время медленного сетевого запроса.

> [!warning]
> Проверка `if !visited[url]` и последующая запись должны находиться в одной критической секции. Иначе две горутины одновременно решат, что URL ещё не посещён.

### Гонки данных и взаимные блокировки

**Data race** — две горутины одновременно обращаются к одной памяти, хотя бы одна пишет, и нет корректной синхронизации.

Проверка:

```bash
go test -race ./...
```

**Deadlock** — горутины навсегда ждут друг друга. Простейший пример:

```go
ch := make(chan int)
ch <- 1 // некому получать, текущая горутина заблокируется
```

Типичные причины:

- отправка без получателя;
- чтение без отправителя;
- ожидание закрытия канала, который никто не закрывает;
- повторная блокировка обычного `sync.Mutex` той же горутиной;
- циклический порядок захвата нескольких блокировок.

## 15. Главные различия и ловушки

### `:=` и `=`

```go
x := 1 // объявить
x = 2  // присвоить
```

`:=` работает только внутри функции и требует хотя бы одно новое имя в текущей области видимости.

### Массив и срез

| Массив `[N]T` | Срез `[]T` |
|---|---|
| длина входит в тип | длина меняется |
| хранит элементы | описывает область базового массива |
| присваивание копирует весь массив | присваивание копирует заголовок среза |
| размер фиксирован | расширяется через `append` |

### `nil`-срез и пустой срез

```go
var a []int      // nil, len=0
b := []int{}     // не nil, len=0
c := make([]int, 0) // не nil, len=0
```

Для большинства операций они ведут себя одинаково, но различие может быть заметно при сравнении с `nil` и сериализации.

### Значение и указатель

| Значение `T` | Указатель `*T` |
|---|---|
| копирует данные | хранит адрес |
| изменение копии не меняет оригинал | можно изменить оригинал |
| не может быть `nil` | может быть `nil` |

### Конкретный тип и интерфейс

- конкретный тип описывает данные и полный набор доступных операций;
- интерфейс описывает требуемое поведение;
- реализация интерфейса неявная;
- интерфейс с типизированным `nil` не равен `nil`.

### `make` и `new`

```go
p := new(int)          // *int, указывает на 0
s := make([]int, 5)    // готовый срез len=5
m := make(map[string]int) // готовая карта
ch := make(chan int)   // готовый канал
```

`make` инициализирует внутреннюю структуру среза, карты или канала и возвращает значение типа `T`. `new(T)` возвращает указатель `*T` на нулевое значение.

### `panic` и `error`

- `error` — ожидаемая проблема, которую вызывающий код может обработать;
- `panic` — нарушение предположений программы или ситуация, в которой обычное продолжение невозможно.

Для обычных ошибок ввода, сети, файлов и валидации следует возвращать `error`, а не вызывать `panic`.

### Конкурентность и безопасность

Запуск функции через `go` сам по себе не делает код безопасным или быстрым. Нужно ответить на вопросы:

1. Кто владеет изменяемыми данными?
2. Как горутины обмениваются результатами?
3. Кто и когда завершает работу?
4. Кто закрывает канал?
5. Как передаётся отмена?
6. Может ли отправитель или получатель остаться ждать навсегда?

## 16. Краткая шпаргалка

```go
// Пакет и импорт
package main
import "fmt"

// Переменные и константа
var x int
y := 42
const Pi = 3.14

// Функция
func add(a, b int) int { return a + b }

// Условие
if x > 0 {
} else {
}

// Цикл
for i := 0; i < 10; i++ {
}

// Switch
switch x {
case 1:
default:
}

// Указатель
p := &x
*p = 10

// Структура
type User struct {
	Name string
	Age  int
}

// Срез
items := []int{1, 2, 3}
items = append(items, 4)

// Карта
counts := make(map[string]int)
counts["go"]++
value, ok := counts["go"]

// Метод
func (u *User) Birthday() {
	u.Age++
}

// Интерфейс
type Writer interface {
	Write([]byte) (int, error)
}

// Проверка ошибки
result, err := operation()
if err != nil {
	return err
}

// Дженерик
func Identity[T any](value T) T {
	return value
}

// Горутина и канал
ch := make(chan int)
go func() { ch <- 42 }()
value = <-ch

// Select
select {
case value := <-ch:
	fmt.Println(value)
default:
	fmt.Println("not ready")
}

// Мьютекс
var mu sync.Mutex
mu.Lock()
defer mu.Unlock()
```

### Полезные команды


## 17. Что изучать после тура

Тур даёт синтаксис и ключевую модель языка, но для практической разработки дальше нужны:

1. **Модули и структура проекта** — `go.mod`, пакеты, `internal`, правила импортов.
2. **Тестирование** — пакет `testing`, табличные тесты, под-тесты, моки через маленькие интерфейсы.
3. **Работа с ошибками** — `%w`, `errors.Is`, `errors.As`, собственные типы ошибок.
4. **Контекст** — `context.Context`, таймауты и отмена операций.
5. **Стандартная библиотека** — `io`, `os`, `net/http`, `encoding/json`, `time`, `sync`.
6. **Конкурентные шаблоны** — worker pool, fan-out/fan-in, graceful shutdown, ограничение числа горутин.
7. **Инструменты** — `gofmt`, `go test`, race detector, `go vet`, профилирование.

> [!summary] Главная мысль тура
> Go строится вокруг небольшого числа простых идей: явных типов и ошибок, композиции вместо классовой иерархии, неявных интерфейсов и встроенных средств конкурентности. Сила языка не в количестве конструкций, а в том, как последовательно они сочетаются.
