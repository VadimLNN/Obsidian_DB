**Состояние (State)** в [[React]] — это специальная переменная, которая содержит информацию о текущей ситуации в компоненте и определяет его поведение и внешний вид в конкретный момент времени. В широком смысле это вся информация, к которой программа имеет доступ в данный момент.

## Ключевые аспекты работы с состоянием:

### 1. Роль состояния и рендеринг

• **Интерактивность:** Состояние является ключом к созданию интерактивных компонентов. Когда пользователь взаимодействует с приложением, состояние может измениться, что вызывает автоматическое **обновление (ререндеринг)** компонента для отражения этих изменений в интерфейсе.

• **Batching (Пакетное обновление):** Важно помнить, что обновление состояния не происходит мгновенно. [[React]] собирает обновления в пакеты и применяет их перед следующим рендерингом для оптимизации производительности.

### 2. Типы состояния в современных приложениях (2025-2026 г.)

Чистая архитектура предполагает разделение состояния на три категории:

• **UI State:** Локальное состояние отдельного компонента (например, открыта ли модалка или какая вкладка активна). Управляется встроенными хуками.

• **App State:** Глобальное состояние клиента (авторизация, тема оформления). Для этого используются такие библиотеки, как **[[Redux]]** или **[[Zustand]]**.

• **Server State:** Данные, полученные из [[API]] (кэшированные данные, статус загрузки). Лучше всего управляется через **TanStack Query (React Query)** или **SWR**.

### 3. Инструменты управления состоянием

React предоставляет два основных хука для работы с локальным состоянием:

• **[[useState]]**: Идеально подходит для простых значений (строки, числа, простые объекты), которые не зависят друг от друга. Он возвращает кортеж из текущего значения и функции для его обновления.

• **[[useReducer]]**: Рекомендуется для управления сложной логикой состояния, когда новое значение зависит от предыдущего или когда объект состояния имеет много связанных свойств.

### 4. Глобальное состояние и передача данных

• **[[Prop Drilling]]:** Это процесс передачи состояния от родителя к глубоко вложенному потомку через промежуточные компоненты, которым эти данные не нужны. Это считается антипаттерном в больших приложениях.

• **[[React Context]]:** Позволяет делиться состоянием между компонентами без ручного прокидывания пропсов. Однако обновления контекста заставляют всех потребителей перерендериваться, поэтому он лучше подходит для редко меняющихся данных.

• **[[Redux]] ([[Redux Toolkit]]):** Хранит всё состояние приложения в одном централизованном и неизменяемом объекте — **store**. Обновления происходят через отправку **actions**, которые обрабатываются **reducers**.

### 5. Важное правило: Иммутабельность

Состояние в React должно обрабатываться как **неизменяемое (immutable)**. Вы никогда не должны изменять `this.state` или переменную состояния напрямую. Вместо этого всегда нужно создавать **копию** данных с необходимыми изменениями (например, через spread-оператор `...`). Современные библиотеки, такие как [[Redux Toolkit]], используют внутри библиотеку **Immer**, которая позволяет писать «мутирующий» код, автоматически превращая его в безопасные иммутабельные обновления.
