Оператор **keyof** и **индексированные типы доступа (Indexed Access Types)** — это продвинутые возможности [[TypeScript]], которые позволяют создавать гибкие и типобезопасные компоненты в [[React]], гарантируя строгую связь между структурами данных и логикой их обработки.

### Оператор keyof

Оператор **keyof** принимает тип объекта и генерирует объединение (union) строковых или числовых литералов, соответствующих его ключам.

- **Принцип работы:** Если у вас есть тип `Laptop` со свойствами `id`, `model` и `releaseDate`, то применение `keyof Laptop` создаст тип `"id" | "model" | "releaseDate"`.
- **Применение в [[React]]:** Этот оператор незаменим при создании универсальных компонентов (например, селекторов или таблиц), где один из пропсов должен указывать на конкретное поле в данных.
- **Типобезопасность:** Использование `keyof` позволяет TypeScript ловить опечатки в названиях полей на этапе компиляции, гарантируя, что передаваемая строка действительно является ключом объекта.

### Индексированные типы доступа (Indexed Types)

Индексированные типы позволяют **получить доступ к типу конкретного свойства** или элемента другого типа.

- **Для объектов:** Используя синтаксис `Type['property']`, можно извлечь тип определенного поля. Например, если поле `id` в типе `Laptop` является строкой, то `Laptop['id']` вернет тип `string`.
- **Для массивов:** Синтаксис `Type[number]` используется для извлечения типа индивидуальных элементов массива. Если у вас есть массив строк `Tabs`, то `Tabs[number]` вернет объединение всех строковых значений, содержащихся в этом массиве.

### Совместное использование в компонентах

В сложных React-компонентах эти техники часто комбинируются с **[[Generics в React|Generics]]**:

1. Компонент принимает массив данных типа `Data`.
2. С помощью `keyof Data` типизируются пропсы, отвечающие за выбор ключевых полей (например, `id` или `label`), что заставляет разработчика выбирать только из существующих свойств объекта.
3. Это избавляет от необходимости «нормализовать» данные перед рендерингом, позволяя компоненту адаптивно работать с любыми структурами.
4. Индексированный доступ помогает извлекать значения по этим ключам внутри компонента, сохраняя при этом информацию об их исходных типах.

Такой подход позволяет строить **типобезопасные переиспользуемые абстракции**, которые «понимают» структуру передаваемых в них данных и предотвращают ошибки доступа к несуществующим свойствам.
