Хук **`useCallback`** — это инструмент производительности в [[React]], который позволяет **мемоизировать само определение функции** между рендерингами. Он предотвращает повторное создание функции при каждом обновлении компонента, если её зависимости не изменились.

### 1. Параметры и синтаксис `useCallback`

```
const memoizedCallback = useCallback(() => {
  // Логика функции
  doSomething(a, b);
}, [a, b]); // Массив зависимостей
```

Хук принимает два аргумента:

1. **Функция:** код, который должен быть мемоизирован.
2. **Массив зависимостей:** список значений, при изменении которых [[React]] создаст **новый экземпляр функции**. Если зависимости пусты `[]`, функция будет создана только один раз при монтировании.

### 2. Зачем это нужно: стабильность ссылок

В [[JavaScript]] функции являются объектами, поэтому при каждом рендеринге компонента создается **новая ссылка** на функцию, даже если её содержимое идентично предыдущему.

Это становится проблемой в следующих случаях:

- **Передача в оптимизированные компоненты:** Если вы передаете функцию как `prop` в дочерний компонент, обернутый в **`React.memo`**, этот компонент будет перерендериваться при каждом обновлении родителя, так как ссылка на функцию всегда "новая". `useCallback` обеспечивает **стабильную ссылку**, позволяя `React.memo` эффективно пропускать лишние отрисовки.
- **Использование в качестве зависимостей других хуков:** Если мемоизированная функция используется внутри `useEffect` другого компонента, стабильная ссылка предотвратит бесконечные циклы или лишние запуски эффекта.

### 3. Использование с TypeScript

[[TypeScript]] обычно автоматически выводит типы аргументов и возвращаемого значения функции. Однако можно указать тип функции явно через универсальный аргумент ([[Generics в React|generic]]):

```
const handleIncrement = useCallback<() => void>(() => {
  setCount(c => c + 1);
}, []);
```

Это полезно для строгого соблюдения контрактов интерфейсов.

### 4. Сравнение с `useMemo`

Хотя оба хука служат для мемоизации, они возвращают разные вещи:

- **`useMemo`** вызывает функцию и мемоизирует **результат** её выполнения.
- **`useCallback`** мемоизирует **саму функцию** (не вызывая её), чтобы её можно было вызвать позже.
- Фактически, `useCallback(fn, deps)` — это эквивалент `useMemo(() => fn, deps)`.

### Важные нюансы из источников:

- **Оптимизация после замеров:** Не следует оборачивать в `useCallback` абсолютно каждую функцию. Это усложняет код и требует ресурсов на хранение ссылок. Оптимизацию рекомендуется проводить только тогда, когда это действительно решает проблемы с производительностью.
- **Риск устаревших замыканий (Stale Closures):** Если внутри функции используются переменные (`props` или `state`), которые **не указаны в массиве зависимостей**, функция "запомнит" их старые значения из того рендера, когда она была создана. Это может привести к логическим ошибкам в приложении.
- **Взаимодействие с `React.memo`:** `useCallback` сам по себе не предотвращает рендеринг компонента, в котором он объявлен. Он приносит пользу только в паре с дочерними компонентами, которые используют механизмы мемоизации.
