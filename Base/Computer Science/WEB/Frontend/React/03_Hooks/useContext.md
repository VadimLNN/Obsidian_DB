**useContext** — это встроенный инструмент [[React]] для управления **глобальным состоянием** и решения проблемы **"[[Prop Drilling]]"** (прокидывания пропсов через множество уровней). Он позволяет компонентам получать доступ к данным напрямую из [[React Context|"контекста"]], независимо от того, насколько глубоко в дереве компонентов они находятся.

## 1. Использование `useContext`

```
const value = useContext(MyContext);
```

Хук принимает один аргумент:

1. **Объект контекста:** объект, созданный функцией `createContext()`.
2. **Возвращаемое значение:** текущее значение контекста, которое определяется ближайшим к компоненту `<MyContext.Provider>` выше по дереву.
3. Механизм обновлений
	• **Триггер рендеринга:** когда значение в `Provider` изменяется, **все компоненты**, использующие `useContext` для этого контекста, **автоматически перерендериваются**.
	• **Синхронизация:** это гарантирует, что все части приложения всегда видят актуальные глобальные данные (например, текущего пользователя или тему).
4. Необходимая инфраструктура
	Для работы хука требуются две составляющие:
		• **createContext****:** создание самого хранилища данных с начальным значением.
		• **Provider****:** компонент-обертка, который "раздает" данные всем потомкам через атрибут `value`.

## 4. Правила использования

• **Верхний уровень:** `useContext` нельзя вызывать внутри условий или циклов.

• **Только функциональные компоненты:** хук не работает в классовых компонентах.

## 5. Типичные сценарии использования (Cross-Cutting Concerns)

Контекст идеально подходит для данных, которые нужны многим компонентам одновременно:

• **Аутентификация:** информация о вошедшем пользователе и токены доступа.

• **Тематизация:** настройки оформления (светлая/темная тема).

• **Локализация:** выбранный язык приложения.

• **Флаги функций:** включение или выключение определенных возможностей интерфейса.

## 6. Пример: Доступ к данным пользователя

```
const UserContext = createContext(null);

function Header() {
  const user = useContext(UserContext); // Получаем данные напрямую
  return <div>Привет, {user?.name}</div>;
}
```

Важные нюансы из источников:

• **Проблема производительности:** Обновление контекста вызывает повторный рендеринг **всех** потребителей. Поэтому в контекст не рекомендуется помещать часто меняющиеся значения.

• **Масштабируемость:** Для очень сложных переходов состояний или огромных приложений вместо контекста часто используют **[[Redux]]** или **Zustand**, так как контекст не является полноценной системой управления состоянием (в нем отсутствуют инструменты отладки, middleware и т.д.).

• **TypeScript:** При создании контекста через `createContext` в [[TypeScript]] обязательно нужно указывать тип данных или дефолтное значение для корректной работы автодополнения и проверок.
