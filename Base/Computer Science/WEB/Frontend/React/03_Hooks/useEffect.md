Хук **`useEffect`** — это один из самых важных инструментов в [[React]], предназначенный для управления **побочными эффектами** (side effects) в функциональных компонентах. Побочным эффектом считается любое действие, которое выполняется вне области видимости возвращаемого компонентом интерфейса: например, запросы к [[API]], подписки на события или ручное манипулирование [[DOM]].

### 1. Параметры `useEffect`

```
useEffect(() => {
  const subscription = someAPI.subscribe();
  
  // Функция очистки (выполнится при размонтировании)
  return () => {
    subscription.unsubscribe();
  };
}, [dependency]); // Массив зависимостей
```

Хук принимает два аргумента:

1. **Функция эффекта:** содержит логику, которая должна быть выполнена. По умолчанию она запускается после каждого рендеринга компонента.
2. **Массив зависимостей (необязательный):** определяет, когда именно нужно перезапустить эффект.

### 2. Управление жизненным циклом через зависимости

Поведение хука кардинально меняется в зависимости от второго аргумента:

- **Массив отсутствует:** эффект запускается **после каждого рендеринга**.
- **Пустой массив `[]`:** эффект запускается только один раз — **при монтировании** компонента (аналог `componentDidMount` в классовых компонентах).
- **Массив со значениями `[prop, state]`:** эффект перезапускается только тогда, когда **изменяется хотя бы одно** из указанных значений.

### 3. Функция очистки (Cleanup)

Эффект может возвращать функцию очистки, которая выполняется перед размонтированием компонента или перед следующим запуском того же эффекта. Это критически важно для предотвращения **утечек памяти**.

- **Пример:** если вы добавляете обработчик событий через `addEventListener`, функция очистки должна его удалить через `removeEventListener`.

### 4. Правила использования хуков

Для `useEffect`, как и для других хуков, действуют строгие правила:

- **Только на верхнем уровне:** нельзя вызывать хук внутри циклов, условий или вложенных функций. Это гарантирует, что хуки всегда вызываются в одном и том же порядке при каждом рендеринге.
- **Только в функциональных компонентах:** хуки не работают в классовых компонентах.

### 5. Работа с асинхронным кодом

`useEffect` **не может напрямую принимать асинхронную функцию** (`async`), так как ожидается, что функция эффекта либо ничего не возвращает, либо возвращает функцию очистки.

- **Правильный паттерн:** создайте асинхронную функцию внутри эффекта и сразу вызовите её:
    
    ```
    useEffect(() => {
      async function fetchData() {
        const response = await getPosts();
        // логика обработки данных
      }
      fetchData();
    }, []);
    ```
    

### 6. Типичный пример: Загрузка данных

При реализации загрузки данных из [[REST API]] часто используется флаг отмены (`cancel`), чтобы избежать обновления состояния, если компонент уже был размонтирован до завершения сетевого запроса:

```
useEffect(() => {
  let cancel = false; // флаг отмены
  getPosts().then((data) => {
    if (!cancel) {
      setPosts(data); // обновление только если компонент еще активен
      setIsLoading(false);
    }
  });
  return () => {
    cancel = true; // очистка при размонтировании
  };
}, []);
```

### Важные нюансы из источников:

- **Двойной запуск:** в режиме разработки (`Strict Mode`) React специально запускает эффекты дважды, чтобы помочь разработчикам обнаружить отсутствие очистки ресурсов.
- **Концентрация:** рекомендуется делать эффекты небольшими, сфокусированными на одной задаче и предсказуемыми.
- **Производительность:** использование `useEffect` для управления данными часто можно заменить более эффективными библиотеками, такими как **React Query (TanStack Query)**, которые берут на себя кэширование и обновление серверного состояния.
