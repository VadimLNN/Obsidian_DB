Хук **`useReducer`** — это продвинутый инструмент в [[React]] для управления состоянием, который является альтернативой `useState`. Он основан на концепциях архитектуры Redux и идеально подходит для управления сложной логикой, когда состояние состоит из нескольких взаимосвязанных частей или когда следующее состояние зависит от предыдущего.

### 1. Синтаксис и параметры

```
const [state, dispatch] = useReducer(reducer, initialState);
```

Хук принимает два основных аргумента:

1. **`reducer`**: Функция-редуктор, которая определяет, как именно изменяется состояние.
2. **`initialState`**: Начальное значение состояния.

Возвращает **кортеж** (массив) из двух элементов:

- **`state`**: Текущее значение состояния.
- **`dispatch`**: Функция, используемая для отправки «действий» (actions), которые инициируют изменения.

### 2. Функция-редуктор (Reducer)

Редуктор — это **чистая функция**, которая принимает текущее состояние и объект действия, а затем возвращает **новое состояние**.

**Основные правила редуктора:**

- **Чистота (Purity):** При одних и тех же входных данных редуктор всегда должен возвращать один и тот же результат. Внутри **запрещены побочные эффекты**: запросы к API, вызовы `Math.random()` или `Date.now()`.
- **Иммутабельность (Неизменяемость):** Редуктор никогда не должен мутировать (изменять) текущий объект `state` напрямую. Вместо этого всегда возвращается **новая копия объекта**, часто создаваемая с помощью spread-оператора (`...state`).
- **Структура:** Обычно логика внутри строится на конструкции `switch`, которая проверяет тип действия (`action.type`).

### 3. Действия (Actions) и Dispatch

- **Action (Действие):** Это обычный JavaScript-объект, описывающий, что произошло в приложении. Он обязан иметь поле **`type`** (обычно строка-константа) и может содержать дополнительные данные (payload).
- **Dispatch (Отправка):** Это единственный способ вызвать изменение состояния. Вы вызываете `dispatch(action)`, React передает это действие в редуктор, вычисляет новое состояние и перерисовывает компонент.

### 4. Когда использовать `useReducer` вместо `useState`?

Хотя `useState` проще, `useReducer` выигрывает в следующих случаях:

- **Сложные объекты состояния**, где свойства зависят друг от друга.
- **Логика обновлений сложна** или требует нескольких шагов.
- **Тестирование:** Поскольку редуктор — это чистая функция, вынесенная за пределы компонента, её легко тестировать независимо от UI.
- **Паттерн "State Reducer":** Позволяет инвертировать контроль над состоянием, давая разработчику-потребителю возможность самому определять правила изменения данных (часто используется в библиотеках).

### 5. Использование с TypeScript

Для максимальной надежности в [[TypeScript]] рекомендуется строго типизировать состояние и все возможные действия через Union Types:

```
type State = { count: number };
type Action =
  | { type: 'increment' }
  | { type: 'decrement' }
  | { type: 'reset', payload: number };

const [state, dispatch] = useReducer<Reducer<State, Action>>(reducer, initialState);
```

Явное указание типов позволяет получать подсказки (IntelliSense) внутри редуктора и отлавливать ошибки при отправке неверных действий еще на этапе написания кода.

### Важные нюансы:

- **Отсутствие мгновенного обновления:** Как и в случае с `useState`, обновления в `useReducer` могут собираться в пакеты (**batching**) для оптимизации производительности.
- **Стабильность функции dispatch:** React гарантирует, что ссылка на функцию `dispatch` остается стабильной и не меняется между рендерами, поэтому её безопасно передавать в `useEffect` или дочерние компоненты без риска лишних перерисовок.
