Хук **`useRef`** — это инструмент в [[React]], который возвращает изменяемый объект-реф, значение которого сохраняется на протяжении всего времени жизни компонента. В отличие от состояния (state), изменение рефа не приводит к повторному рендерингу интерфейса, что делает его идеальным для хранения данных, не влияющих на визуальное отображение.

### 1. Параметры и синтаксис `useRef`

```
const myRef = useRef(initialValue);

// Доступ к значению
console.log(myRef.current);

// Обновление значения
myRef.current = newValue;
```

Хук принимает один аргумент:

1. **Начальное значение (initialValue):** значение, которое будет записано в свойство `.current` объекта при первом рендеринге.
2. **Возвращаемое значение:** объект с единственным свойством **`.current`**, который остается неизменным (тем же самым объектом) между рендерами.

### 2. Ключевые особенности и отличия от State

Поведение `useRef` имеет два критических отличия от `useState`:

- **Персистентность (Persistence):** Значение переменной сохраняется (не сбрасывается) при каждом повторном рендеринге компонента.
- **Отсутствие триггера обновлений:** Изменение свойства `.current` **не вызывает повторный рендеринг**. Это позволяет выполнять императивные действия или хранить промежуточные данные без лишних циклов отрисовки.

### 3. Основные сценарии использования

Хук `useRef` чаще всего применяется в двух случаях:

- **Доступ к DOM-узлам:** Это наиболее распространенный способ взаимодействия с HTML-элементами напрямую (например, для управления фокусом, программного вызова анимаций или интеграции со сторонними библиотеками, работающими с DOM вне React).
- **Хранение изменяемых значений:** Хранение данных, которые должны быть доступны во время работы компонента, но не должны влиять на JSX (например, ID таймеров `setTimeout`, переменные для отслеживания предыдущих значений пропсов или флаги отмены запросов).

### 4. Использование с TypeScript

В проектах на TypeScript типы для `useRef` можно указывать явно, что особенно важно при работе с DOM-элементами, так как компилятор не всегда может вывести тип автоматически:

```
// Типизация для доступа к элементу ввода
const inputRef = useRef<HTMLInputElement>(null);

const focusInput = () => {
  // Использование опциональной цепочки для безопасности
  inputRef.current?.focus();
};

return <input ref={inputRef} type="text" />;
```

Указание типа (например, `HTMLButtonElement` или `HTMLInputElement`) обеспечивает работу IntelliSense и проверку типов при обращении к методам элемента.

### 5. Правила использования хука

Для `useRef` действуют те же "правила хуков", что и для других функций React:

- **Только на верхнем уровне:** Вызов хука не должен находиться внутри условий, циклов или вложенных функций.
- **Только в функциональных компонентах:** Хуки не поддерживаются внутри классовых компонентов.
- **Ограничение функциональных компонентов:** Рефы нельзя использовать для доступа к функциональным компонентам извне напрямую (через атрибут `ref`), так как у них нет "экземпляра поддержки" (если не используется специальный механизм `forwardRef`).

### Важные нюансы из источников:

- **Оператор опциональной цепочки (`?.`):** Поскольку свойство `.current` инициализируется как `null` до монтирования компонента, при вызове методов (например, `.focus()`) рекомендуется использовать `?.`, чтобы избежать ошибок выполнения.
- **Смешивание задач:** Не рекомендуется изменять рефы непосредственно в теле функции компонента (во время рендеринга). Для взаимодействия с DOM или изменения рефов, зависящих от состояния, лучше использовать `useEffect`.
- **Мгновенное обновление:** В отличие от `useState`, обновление `.current` происходит мгновенно, не дожидаясь следующего цикла рендеринга.
