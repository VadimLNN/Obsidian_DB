**Хуки (Hooks)** — это специальные функции [[React]], которые позволяют «подключаться» к [[Состояние (State)|состоянию]] и методам жизненного цикла из функциональных компонентов. Они были представлены в версии 16.8 и с тех пор стали основным стандартом разработки, сделав классовые компоненты практически устаревшими.

### Зачем нужны хуки?

До появления хуков функциональные компоненты были «глупыми» и могли только отображать данные (props). Хуки дали им следующие преимущества:

1. **Интерактивность:** Возможность хранить данные в состоянии напрямую в функции.
2. **Лаконичность:** Реализация той же логики в функциональных компонентах требует меньше кода, чем в классах.
3. **Переиспользование:** Логику (например, загрузку данных или работу с формами) легче извлекать в [[Custom Hooks|пользовательские хуки]] и использовать в разных частях приложения.
4. **Чистота архитектуры:** Хуки позволяют разделять связанные части кода по функциональному признаку, а не разбрасывать их по разным методам жизненного цикла (как `componentDidMount` и `componentWillUnmount`).

### Группировка основных хуков

Для удобства понимания хуки можно разделить на несколько функциональных категорий:

#### 1. Управление состоянием

Эти хуки позволяют компоненту «запоминать» информацию между рендерингами.

- **[[useState]]**: Базовый инструмент для добавления простой переменной состояния (например, строка, число или булево значение).
- **[[useReducer]]**: Рекомендуется для управления сложной логикой, когда состояние состоит из множества взаимосвязанных свойств или когда следующее состояние зависит от предыдущего.

#### 2. Работа с побочными эффектами

Побочные эффекты — это любые действия, которые выполняются вне области отрисовки интерфейса.

- **[[useEffect]]**: Предназначен для выполнения сетевых запросов, подписок на события или ручного манипулирования [[DOM]]. Он заменяет классические методы `componentDidMount`, `componentDidUpdate` и `componentWillUnmount`.

#### 3. Сохранение ссылок и объектов

Хуки для работы с данными, которые должны сохраняться на протяжении всей «жизни» компонента, но не обязательно вызывать обновление экрана.

- **[[useRef]]**: Возвращает объект-реф, значение которого сохраняется между рендерами. Изменение рефа **не вызывает повторный рендеринг**. Обычно используется для доступа к DOM-узлам или хранения идентификаторов таймеров.

#### 4. Оптимизация производительности

Используются для «запоминания» (мемоизации) результатов, чтобы избежать лишних вычислений или перерисовок дочерних элементов.

- **[[useMemo]]**: Мемоизирует **результат** ресурсозатратных вычислений.
- **[[useCallback]]**: Мемоизирует **само определение функции**, предотвращая её создание при каждом обновлении. Это полезно при передаче функций в оптимизированные дочерние компоненты.

#### 5. Глобальное состояние

- **[[useContext]]**: Позволяет потреблять значения из [[React Context]] напрямую, избавляя от необходимости «прокидывания пропсов» ([[Prop Drilling|prop drilling]]) через все уровни дерева компонентов.

### Правила использования хуков

Чтобы React мог корректно отслеживать состояние, все хуки должны подчиняться двум строгим правилам:

1. **Только на верхнем уровне:** Нельзя вызывать хуки внутри условий, циклов или вложенных функций. Порядок вызовов хуков должен быть идентичным при каждом рендеринге.
2. **Только в функциональных компонентах:** Хуки не работают внутри обычных JavaScript-функций или классовых компонентов (за исключением пользовательских хуков, которые сами вызывают другие хуки).

### Как это работает «под капотом»

При первом вызове хука [[React]] создает в памяти **экземпляр поддержки** для функционального компонента. В этом объекте хранятся все данные состояния и ссылки. Когда вызывается функция обновления (например, из `useState`), [[React]] планирует **ререндеринг**, сравнивает виртуальную [[DOM]] с текущей и точечно обновляет только измененные части.
