SPA (Single Page Application) — это тип веб‑приложения, которое работает в рамках **одной** HTML‑страницы и динамически обновляет содержимое с помощью [[JavaScript]], вместо полной перезагрузки страницы при каждом переходе.

## Как это работает

- При первом заходе загружается одна страница + JS/CSS (часто довольно «толстый» бандл).
- Дальше при кликах по ссылкам SPA не запрашивает новый [[HTML]], а делает [[API]]‑запросы (обычно [[JSON]]) и меняет [[DOM]] на лету.
- Визуально кажется, что ты «переходишь по страницам», но на уровне браузера документ остаётся тем же, меняется только контент и [[URL]] через History API.

## Зачем вообще SPA

- Более «приложенческий» [[UX]]: быстрые переходы, без мерцаний и белых экранов между страницами.
- Меньше нагрузки на сервер: сервер отдает данные, а не HTML‑шаблоны.
- Удобно делить фронт и бэк: отдельный SPA ([[React]], [[Vue]], [[Angular]]) + отдельный [[API]].

## Минусы и подводные камни

- Первый заход может быть медленным (нужно скачать весь JS, пока не начнётся рендер).
- Сложнее [[SEO]], навигация и аналитика, если не использовать [[SSR]]/пререндер.
- Больше ответственности на фронтенд: состояние, безопасность, производительность.
    

## Простой пример

Обычный сайт ([[MPA]]): клик по ссылке → браузер загружает **новую** страницу с сервера.  
SPA: клик по ссылке → JS меняет содержимое текущей страницы и URL, а с сервера прилетают только данные, без полного HTML.
