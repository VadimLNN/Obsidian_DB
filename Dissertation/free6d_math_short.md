# Free6D.3-2.150 — кратко о математике

## 1. Что делает математика

Пользователь задаёт желаемое положение платформы:

```text
X, Y, Z, Rx, Ry, Rz
```

Это 6 степеней свободы:

- `X, Y, Z` — перемещение;
- `Rx, Ry, Rz` — вращение вокруг осей.

Программа должна преобразовать эту позу в 6 команд контроллеру:

```text
q1 q2 q3 q4 q5 q6
```

Основная цепочка:

```text
X Y Z Rx Ry Rz
        ↓
перенос t + поворот Q
        ↓
точки p1 p2 p3
        ↓
R1 T1 L1
R2 T2 L2
R3 T3 L3
        ↓
q1 ... q6
        ↓
контроллер
```

---

## 2. Это не обычная платформа Стюарта

В найденной программной модели используется не схема:

```text
6 ног → 6 длин
```

а:

```text
3 расчётные ветви
×
R, T, L
```

При этом командными являются 6 координат `R/T`, а `L1...L3` вычисляются дополнительно.

---

## 3. Три ветви

Ветви расположены через `120°`:

| Ветвь | Угол `φ_i` |
|---|---:|
| 1 | `0°` |
| 2 | `120°` |
| 3 | `240°` |

Для удобства:

```text
c_i = cos(φ_i)
s_i = sin(φ_i)
```

Поэтому:

| Ветвь | `c_i` | `s_i` |
|---|---:|---:|
| 1 | `1` | `0` |
| 2 | `-0.5` | `0.866` |
| 3 | `-0.5` | `-0.866` |

---

## 4. Точки b1, b2, b3

В нулевой позиции задаются три расчётные точки:

```text
b1
b2
b3
```

Они расположены на радиусе:

```text
r = 39.5809191
```

и образуют треугольник вокруг центра платформы.

---

## 5. Самая важная формула

После перемещения платформы:

```text
p_i = t + Q · b_i
```

где:

```text
b_i — исходная точка
Q   — поворот
t   — перенос
p_i — новое положение точки
```

То есть:

```text
b_i
↓ повернули
Q · b_i
↓ добавили перенос
p_i
```

`p_i` — это позиция i-й расчётной точки, связанной с i-й ветвью.

---

## 6. Расчёт R, T и L

После получения:

```text
p_i = (X_i, Y_i, Z_i)
```

вычисляются:

```text
R_i = c_i·X_i + s_i·Y_i - r - Z_i·cot(α)

T_i = s_i·X_i - c_i·Y_i

L_i = Z_i / sin(α)
```

где:

```text
α = 30°
```

Упрощённо можно воспринимать:

```text
R — одна локальная координата ветви
T — вторая локальная координата ветви
L — координата, связанная с высотой
```

Точный физический смысл `R/T/L` для конкретных деталей механизма ещё требует проверки.

---

## 7. Команды контроллеру

Из `R` и `T` формируются 6 команд:

```text
q1 = -R1
q2 = -T1

q3 = -R2
q4 = -T2

q5 = -R3
q6 = -T3
```

То есть:

```text
q = -(R1, T1, R2, T2, R3, T3)
```

`L1, L2, L3` в найденной карте отдельными командами не отправляются.

---

## 8. Пример движения по X

Если платформа движется только:

```text
X = d
```

то:

```text
q1 = -d
q2 = 0

q3 = d/2
q4 = -√3·d/2

q5 = d/2
q6 = √3·d/2
```

Для:

```text
d = 4.567 мм
```

получается:

```text
[-4.567000,
  0,
  2.283500,
 -3.955138,
  2.283500,
  3.955138]
```

Этот результат совпал с разобранным ROUT-фрагментом программы.

---

## 9. Повороты

Поворот задаётся матрицей:

```text
Q
```

Она определяет новую ориентацию платформы.

Важно:

```text
Rx → Ry
```

и:

```text
Ry → Rx
```

могут дать разные результаты.

Поэтому порядок вращений имеет значение.

SDK поддерживает несколько Euler Order, например:

```text
ZYX
XYZ
ZXY
...
```

---

## 10. Tool offset

Кроме системы координат платформы существует система координат инструмента:

```text
Platform zero
Tool zero
```

Tool может находиться не в центре платформы.

Связь:

```text
D = A⁻¹ P A
```

где:

```text
P — движение Platform
D — движение Tool
A — Tool offset
```

Это позволяет задавать движение относительно рабочей точки инструмента.

При вращении вокруг Tool центр платформы может одновременно перемещаться.

---

## 11. Inverse и Forward Kinematics

### Inverse Kinematics — IK

```text
X Y Z Rx Ry Rz
        ↓
      IK
        ↓
q1 ... q6
```

Это основная восстановленная математика проекта.

### Forward Kinematics — FK

```text
q1 ... q6
        ↓
      FK
        ↓
X Y Z Rx Ry Rz
```

FK сложнее и обычно решается итерационно.

---

## 12. Якобиан

Якобиан нужен для работы со скоростями:

```text
q̇ = J · v
```

где `v` содержит:

```text
скорость X Y Z
+
угловую скорость вокруг X Y Z
```

То есть Якобиан отвечает на вопрос:

> С какой скоростью должны изменяться `q1...q6` при заданной скорости платформы?

Также по Якобиану можно анализировать плохие или близкие к сингулярным положения.

---

## 13. Ограничения

Паспортные пределы:

| Координата | Предел |
|---|---:|
| X | ±10 мм |
| Y | ±10 мм |
| Z | ±5 мм |
| Rx | ±9° |
| Ry | ±8° |
| Rz | ±14° |

Но это не означает, что все максимумы можно использовать одновременно.

Нужно дополнительно проверять:

```text
q
L
столкновения
ходы деталей
кабели
нагрузку
Якобиан
```

---

## 14. Траектории

Недостаточно вычислить только начало и конец.

Правильная схема:

```text
Pose(t)
   ↓
IK
   ↓
q1(t)...q6(t)
   ↓
контроллер
```

Для плавного движения задаётся функция разгона и торможения.

Например:

```text
s(u) = 10u³ - 15u⁴ + 6u⁵
```

Она обеспечивает нулевую скорость и ускорение в начале и конце движения.

---

# Главное

Всю математику Free6D можно свести к следующей цепочке:

```text
Желаемая поза
X Y Z Rx Ry Rz
        ↓
t + Q
        ↓
b1 b2 b3
        ↓
p1 p2 p3
        ↓
R/T/L каждой ветви
        ↓
q1...q6
        ↓
контроллер
        ↓
физическое движение
```

Самая важная формула:

```text
p_i = t + Q·b_i
```

После неё:

```text
p_i
↓
R_i T_i L_i
↓
q1...q6
```

Именно это является основой восстановленной кинематики Free6D.

## Что пока не доказано

Пока нельзя точно утверждать, какая конкретная физическая деталь соответствует `R`, `T` и `L`.

Это необходимо дополнительно сопоставить с:

```text
STEP-моделью
реальной механикой
SDK
логами
экспериментами
```
