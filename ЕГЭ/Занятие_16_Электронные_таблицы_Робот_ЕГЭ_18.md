# Занятие 16. Продвинутые электронные таблицы — Робот и динамическое программирование

**ЕГЭ по информатике — задание №18**

Цель занятия: научиться моделировать движение Робота в электронной таблице и находить оптимальный результат.

В актуальном №18 требуется:

```text
смоделировать возможные действия Робота
+
выбрать оптимальный вариант
```

Обычно оптимизация означает:

```text
максимальную сумму
или
минимальную сумму
```

на допустимом маршруте.

---

# 1. Что здесь нового по сравнению с №9

В задании №9 мы в основном:

```text
проверяли строки таблицы
считали повторы
использовали условия и функции
```

В №18 таблица становится **моделью движения**.

Каждая клетка хранит некоторое число:

```text
стоимость
добычу
штраф
очки
```

Робот движется по таблице по заданным правилам.

Нужно не просто просуммировать числа, а выбрать:

```text
лучший маршрут
```

---

# 2. Учебная модель

Во всех задачах занятия, если не сказано обратное:

```text
старт: A1
финиш: правая нижняя клетка

разрешённые движения:
→ вправо
↓ вниз
```

В сумму включаются:

```text
стартовая клетка
все промежуточные клетки
финишная клетка
```

`X` означает:

```text
клетка запрещена
Робот не может в неё заходить
```

На настоящем ЕГЭ всегда нужно читать условие конкретного файла: направления движения и смысл чисел могут отличаться.

---

# 3. Почему полный перебор маршрутов плох

Пусть таблица:

```text
20 × 20
```

Робот идёт только:

```text
вправо
вниз
```

Маршрутов очень много.

Перебирать каждый маршрут вручную бессмысленно.

Нам нужно для каждой клетки хранить только:

```text
лучший результат попадания в неё
```

Это и есть идея:

```text
динамического программирования
```

---

# 4. Главная формула для максимума

Пусть Робот приходит в клетку:

```text
C4
```

Он мог прийти только:

```text
из B4
или
из C3
```

Значит:

```text
Best(C4)
=
Value(C4)
+
MAX(
    Best(B4),
    Best(C3)
)
```

В электронной таблице:

```text
=Data!C4+МАКС(B4;C3)
```

или в английском интерфейсе:

```text
=Data!C4+MAX(B4,C3)
```

---

# 5. Формула для минимума

Если нужен маршрут с минимальной суммой:

```text
Best(C4)
=
Value(C4)
+
MIN(
    Best(B4),
    Best(C3)
)
```

Формула:

```text
=Data!C4+МИН(B4;C3)
```

---

# 6. Стартовая клетка

Для `A1` предыдущих клеток нет.

Поэтому:

```text
Best(A1) = Value(A1)
```

Если в исходной таблице:

```text
A1 = 5
```

то в таблице динамики:

```text
A1 = 5
```

---

# 7. Первая строка

В первую строку нельзя прийти сверху.

Поэтому:

```text
Best(B1)
=
Value(B1) + Best(A1)
```

```text
Best(C1)
=
Value(C1) + Best(B1)
```

и так далее.

---

# 8. Первый столбец

Аналогично:

```text
Best(A2)
=
Value(A2) + Best(A1)
```

```text
Best(A3)
=
Value(A3) + Best(A2)
```

---

# 9. Пример

Исходная таблица:

|   | A | B | C |
|---|---:|---:|---:|
| 1 | 5 | 2 | 8 |
| 2 | 1 | 7 | 3 |
| 3 | 4 | 6 | 9 |

Ищем максимум.

Начинаем:

```text
A1 = 5
```

Первая строка:

```text
B1 = 5 + 2 = 7
C1 = 7 + 8 = 15
```

Первый столбец:

```text
A2 = 5 + 1 = 6
A3 = 6 + 4 = 10
```

Клетка:

```text
B2
```

```text
= 7 + MAX(7; 6)
= 14
```

Клетка:

```text
C2
```

```text
= 3 + MAX(15; 14)
= 18
```

И так далее.

Финальная таблица максимумов:

|   | A | B | C |
|---|---:|---:|---:|
| 1 | 5 | 7 | 15 |
| 2 | 6 | 14 | 18 |
| 3 | 10 | 20 | 29 |

Ответ:

```text
29
```

---

# 10. Почему можно брать только лучший предыдущий результат

Допустим, в `C4` можно прийти:

```text
из B4 с суммой 40
из C3 с суммой 35
```

Текущая клетка:

```text
7
```

Если ищем максимум:

```text
40 + 7 = 47
35 + 7 = 42
```

Любой путь, который пришёл в `B4` хуже 40, уже никогда не станет лучше после одинакового продолжения.

Поэтому достаточно хранить:

```text
только лучший результат для клетки
```

---

# 11. Запрещённые клетки

Пусть:

```text
C3 = X
```

Робот не может:

```text
войти в C3
выйти из C3
```

В таблице динамики такую клетку нельзя случайно использовать как обычный ноль.

Это одна из главных ловушек №18.

---

# 12. Как обозначать стену при поиске максимума

Удобная техническая идея:

```text
запрещённая клетка = очень маленькое число
```

Например:

```text
-10^15
```

Тогда:

```text
MAX(...)
```

никогда не выберет путь через стену, если существует нормальный путь.

---

# 13. Стена при поиске минимума

Для минимума наоборот:

```text
запрещённая клетка = очень большое число
```

Например:

```text
10^15
```

Иначе `MIN` может случайно выбрать стену.

---

# 14. Недостижимая клетка

Не только сама клетка `X` может быть недостижимой.

Например:

```text
A X
X 5
```

Клетка со значением `5` формально не является стеной.

Но из старта до неё:

```text
нет допустимого маршрута
```

Следовательно её тоже нельзя рассматривать как обычную доступную клетку.

---

# 15. Отдельный лист — лучший способ

Удобно использовать два листа:

```text
Data — исходная таблица
Max  — максимальные суммы
Min  — минимальные суммы
```

Это уменьшает риск случайно затереть исходные данные.

---

# 16. Формулы на листе Max

Пусть исходные числа находятся на:

```text
Data
```

Тогда:

### Старт

```text
=Data!A1
```

### Первая строка

```text
=Data!B1+A1
```

### Первый столбец

```text
=Data!A2+A1
```

### Остальные клетки

```text
=Data!B2+МАКС(A2;B1)
```

После этого формулу можно протянуть.

---

# 17. Формулы на листе Min

Всё то же самое, только:

```text
МАКС
```

заменяется на:

```text
МИН
```

---

# 18. Почему нельзя просто использовать СУММ

Формула:

```text
=СУММ(A1:F10)
```

считает вообще все клетки диапазона.

Но Робот проходит только:

```text
по одному маршруту
```

Поэтому задача №18 — не задача на обычную сумму.

---

# 19. Восстановление маршрута

Если требуется понять сам оптимальный путь, начинаем с финиша.

Допустим:

```text
Best(D4) = 60
```

Смотрим, откуда он мог прийти:

```text
C4
D3
```

Для максимума выбираем ту предыдущую клетку, значение которой использовалось в:

```text
MAX
```

Далее идём назад до старта.

---

# 20. Если предыдущие значения одинаковые

Например:

```text
Best(C4) = 30
Best(D3) = 30
```

Тогда оптимальных путей может быть:

```text
несколько
```

Но если спрашивается только:

```text
максимальная сумма
```

это не проблема.

---

# 21. Отрицательные числа

Динамическое программирование работает и с отрицательными значениями.

Например:

```text
5
-100
8
```

Алгоритм всё равно выбирает лучший допустимый маршрут.

Нельзя рассуждать:

```text
просто идти по самым большим соседним числам
```

Локально лучший выбор не всегда даёт глобально лучший путь.

---

# 22. Жадный алгоритм здесь не работает

Пусть:

```text
     9    1
5
     8  100
```

Если сразу выбрать:

```text
9
```

это кажется выгоднее.

Но путь через:

```text
8 → 100
```

может дать намного больший итог.

Поэтому:

```text
выбирать просто большую соседнюю клетку нельзя
```

Нужна таблица динамики.

---

# 23. Почему таблица заполняется сверху вниз

Для вычисления:

```text
B2
```

нам уже нужны:

```text
A2
B1
```

Следовательно предыдущие клетки должны быть рассчитаны раньше.

При движениях:

```text
→
↓
```

удобно заполнять таблицу:

```text
слева направо
сверху вниз
```

---

# 24. Сколько ходов будет в прямоугольной таблице

Из:

```text
A1
```

в:

```text
D4
```

нужно:

```text
3 шага вправо
3 шага вниз
```

Всего:

```text
6 ходов
```

При этом посещено клеток:

```text
7
```

То есть:

```text
ходов = клеток маршрута - 1
```

---

# 25. Универсальный алгоритм №18

```text
1. Прочитать допустимые движения Робота.
2. Проверить, что входит в сумму.
3. Найти старт и финиш.
4. Отметить запрещённые клетки.
5. Создать вспомогательную таблицу.
6. Заполнить старт.
7. Заполнить крайние строку/столбец.
8. Для остальных клеток:
   Value + MAX(...)
   или
   Value + MIN(...)
9. Протянуть формулы.
10. Взять значение в финише.
11. Проверить несколько клеток вручную.
```

# 26. Типичные ошибки

## Ошибка 1

Суммировать исходную таблицу вместо построения маршрута.

## Ошибка 2

Использовать:

```text
MAX
```

когда требуется минимум.

## Ошибка 3

Считать стену обычным нулём.

## Ошибка 4

Забыть включить стоимость стартовой или конечной клетки.

## Ошибка 5

Разрешить Роботу движение, которого нет в условии.

Например:

```text
диагональ
```

хотя разрешены только:

```text
→ и ↓
```

## Ошибка 6

Считать лучший ход локально:

```text
«из двух соседей пойду в больший»
```

вместо расчёта оптимальной суммы до каждой клетки.

# Python для проверки

Основной навык №18 — электронная таблица, но ответ удобно проверять кодом.

```python
grid = [
    [5, 2, 8],
    [1, 7, 3],
    [4, 6, 9],
]

rows = len(grid)
cols = len(grid[0])

dp = [[0] * cols for _ in range(rows)]

dp[0][0] = grid[0][0]

for c in range(1, cols):
    dp[0][c] = dp[0][c - 1] + grid[0][c]

for r in range(1, rows):
    dp[r][0] = dp[r - 1][0] + grid[r][0]

for r in range(1, rows):
    for c in range(1, cols):
        dp[r][c] = (
            grid[r][c]
            + max(dp[r - 1][c], dp[r][c - 1])
        )

print(dp[-1][-1])
```

Результат:

```text
29
```

# Python со стенами

```python
grid = [
    [4, 2, None, 8],
    [6, 5, 3, 1],
    [None, 7, 4, 9],
    [2, 1, 6, 5],
]

rows = len(grid)
cols = len(grid[0])

dp = [[None] * cols for _ in range(rows)]

dp[0][0] = grid[0][0]

for r in range(rows):
    for c in range(cols):
        if grid[r][c] is None:
            continue

        if r == 0 and c == 0:
            continue

        previous = []

        if r > 0 and dp[r - 1][c] is not None:
            previous.append(dp[r - 1][c])

        if c > 0 and dp[r][c - 1] is not None:
            previous.append(dp[r][c - 1])

        if previous:
            dp[r][c] = grid[r][c] + max(previous)

print(dp[-1][-1])
```

# Что ученик обязан вынести

```text
1. №18 — задача на оптимальный маршрут.

2. При движении → и ↓

   слева и сверху.

3. Максимум:
   Value + MAX(left; up).

4. Минимум:

8. Недостижимая клетка тоже не должна

   не гарантирует лучший полный маршрут.

    моделировать задачу прямо
    в электронной таблице.
```
