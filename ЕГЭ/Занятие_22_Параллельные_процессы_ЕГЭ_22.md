# Занятие 22. Параллельные процессы и зависимости

**ЕГЭ по информатике — задание №22**

Цель занятия: научиться моделировать выполнение зависимых процессов и отвечать на типовые вопросы:

- когда начнётся [[Base/Computer Science/OS/Linux/Administration/Процессы и сигналы|процесс]];
- когда он завершится;
- через сколько миллисекунд завершатся все процессы;
- сколько процессов выполняется одновременно;
- сколько процессов завершилось к заданному моменту;
- какой процесс завершится последним;
- как найти критический путь;
- как определить максимальную длительность максимального параллелизма.

В №22 дана совокупность процессов. Часть процессов независимы и может выполняться параллельно, а часть запускается только после завершения процессов, от которых она зависит.

# 1. Как выглядит таблица №22

Типичная структура:

| ID процесса | Время выполнения, мс | ID процессов, от которых зависит |
|---:|---:|:---|
| 1 | 4 | 0 |
| 2 | 3 | 0 |
| 3 | 1 | 1; 2 |
| 4 | 7 | 3 |

Запись:

```text
0
```

означает:

```text
процесс независимый
```

Запись:

```text
1; 2
```

означает:

```text
процесс может начаться только после завершения
И процесса 1,
И процесса 2.
```

---

# 2. Независимые процессы

Если процесс не зависит ни от кого, он может начать работу сразу:

```text
start = 0
```

Если его длительность:

```text
4 мс
```

то:

```text
finish = 4
```

При нумерации миллисекунд с 1 он выполняется:

```text
на 1-й, 2-й, 3-й и 4-й мс
```

---

# 3. Зависимый процесс

Пусть:

```text
процесс 3 зависит от 1 и 2
```

Процесс 1 завершился в момент:

```text
4
```

Процесс 2:

```text
7
```

Тогда процесс 3 обязан ждать:

```text
оба результата
```

Поэтому:

```text
start(3) = max(4, 7) = 7
```

---

# 4. Главная формула

Для процесса `B`:

```text
start(B)
=
max(finish всех зависимостей B)
```

Если зависимостей нет:

```text
start(B) = 0
```

Затем:

```text
finish(B)
=
start(B) + duration(B)
```

---

# 5. Почему берём MAX, а не сумму

Пусть процесс зависит от:

```text
A
C
```

и они независимы друг от друга.

Они выполняются:

```text
ПАРАЛЛЕЛЬНО
```

Если:

```text
A заканчивается в 5
C заканчивается в 8
```

следующий процесс может стартовать:

```text
в момент 8
```

а не:

```text
5 + 8 = 13
```

---

# 6. Пример

| ID | Время | Зависимости |
|---:|---:|:---|
| 1 | 4 | 0 |
| 2 | 6 | 0 |
| 3 | 3 | 1; 2 |

Получаем:

```text
finish(1) = 4
finish(2) = 6
```

Для процесса 3:

```text
start(3) = max(4, 6) = 6
```

```text
finish(3) = 6 + 3 = 9
```

Все процессы закончатся через:

```text
9 мс
```

---

# 7. Минимальное время выполнения всей совокупности

Когда все независимые процессы стартуют максимально рано:

```text
общее время
=
максимальное finish среди всех процессов
```

То есть:

```python
max(finish.values())
```

---

# 8. Критический путь

Цепочка зависимостей, определяющая общее время выполнения, называется:

```text
критическим путём
```

Если:

```text
1 → 4 → 7 → 10
```

имеет суммарную длительность:

```text
25 мс
```

и никакая другая цепочка не длиннее, именно она определяет момент окончания всей системы.

---

# 9. На какой миллисекунде выполняется процесс

Это особенно важно для современных формулировок №22.

Пусть:

```text
start = 6
duration = 7
finish = 13
```

Тогда процесс выполняется на миллисекундах:

```text
7, 8, 9, 10, 11, 12, 13
```

Для `t`-й миллисекунды:

```text
start < t <= finish
```

В Python:

```python
if start < t <= finish:
    ...
```

---

# 10. Частая ошибка на границе

Если:

```text
finish = 13
```

процесс **выполняется на 13-й мс**.

Если:

```text
start = 13
```

то его первая рабочая миллисекунда:

```text
14-я
```

Это связано с принятой в заданиях нумерацией:

```text
start = 0
→ первая миллисекунда = 1
```

# 11. Сколько процессов завершилось к моменту T

Нужны процессы:

```text
finish <= T
```

Python:

```python
sum(
    finish[p] <= T
    for p in finish
)
```

---

# 12. Сколько процессов выполняется на T-й мс

```python
sum(
    start[p] < T <= finish[p]
    for p in processes
)
```

---

# 13. Максимальный параллелизм

Можно перебрать все миллисекунды:

```python
mx = 0

for t in range(1, total + 1):
    count = sum(
        start[p] < t <= finish[p]
        for p in processes
    )

    mx = max(mx, count)

print(mx)
```

# 14. Длительность максимального параллелизма

Пусть количество одновременно работающих процессов:

```text
1-я мс → 3
2-я мс → 3
3-я мс → 4
4-я мс → 4
5-я мс → 4
6-я мс → 2
```

Максимум:

```text
4 процесса
```

Он держится:

```text
3 мс подряд
```

Ответ:

```text
3
```

---

# 15. Не просто количество миллисекунд

Если максимум встречается:

```text
3–5-я мс
```

и отдельно:

```text
10–11-я мс
```

то максимальная **длина непрерывного отрезка**:

```text
3
```

а не:

```text
3 + 2 = 5
```

---

# 16. Рекурсивный способ

Удобнее всего считать время окончания процесса.

```python
from functools import lru_cache

time = {
    1: 4,
    2: 6,
    3: 3,
}

deps = {
    1: [],
    2: [],
    3: [1, 2],
}

@lru_cache(None)
def finish(p):
    if not deps[p]:
        return time[p]

    return (
        time[p]
        + max(finish(x) for x in deps[p])
    )
```

---

# 17. Время начала

После вычисления `finish`:

```python
start = finish(p) - time[p]
```

Например:

```python
f = finish(3)
s = f - time[3]
```

---

# 18. Почему нужна мемоизация

Процесс может использоваться как зависимость:

```text
для нескольких других процессов
```

Без кэша его цепочка будет вычисляться повторно.

Поэтому:

```python
@lru_cache(None)
```

очень удобен.

---

# 19. Полный Python-шаблон

```python
from functools import lru_cache

duration = {
    1: 4,
    2: 3,
    3: 2,
    4: 5,
}

deps = {
    1: [],
    2: [],
    3: [1],
    4: [1, 2],
}

@lru_cache(None)
def finish(p):
    if not deps[p]:
        return duration[p]

    return (
        duration[p]
        + max(finish(x) for x in deps[p])
    )

start = {
    p: finish(p) - duration[p]
    for p in duration
}

end = {
    p: finish(p)
    for p in duration
}

print(max(end.values()))
```

# 20. Как обработать таблицу из файла

В реальном задании обычно приложен файл:

```text
.xlsx
.ods
```

Удобный путь на занятии:

```text
1. открыть файл в Calc / Excel;
2. при необходимости сохранить копию как CSV;
3. прочитать CSV стандартным Python.
```

Пример:

```python
import csv

duration = {}
deps = {}

with open(
    "22.csv",
    encoding="utf-8-sig"
) as f:
    reader = csv.reader(f, delimiter=";")

    next(reader)

    for row in reader:
        pid = int(row[0])
        duration[pid] = int(row[1])

        if row[2] == "0":
            deps[pid] = []
        else:
            deps[pid] = list(
                map(int, row[2].split())
            )
```

Формат CSV бывает разным, поэтому разделители нужно смотреть по конкретному файлу.

# 21. Решение в электронной таблице

Для небольшого файла можно добавить столбцы:

```text
Start
Finish
```

Независимый процесс:

```text
Start = 0
Finish = Duration
```

Зависимый:

```text
Start = MAX(Finish зависимостей)
Finish = Start + Duration
```

Такой способ особенно удобен, когда зависимостей немного и они легко просматриваются.

# 23. Процесс может ждать, ничего не выполняя

Если одна зависимость закончилась:

```text
в 5 мс
```

а другая:

```text
в 20 мс
```

следующий процесс всё равно ждёт до:

```text
20 мс
```

Промежуток ожидания не прибавляется отдельно.

Он уже отражён через:

```text
max(...)
```

# 24. Независимость не означает одновременное завершение

Все независимые процессы стартуют:

```text
в момент 0
```

Но если длительности:

```text
2
5
9
```

они завершаются:

```text
2
5
9
```

# 26. Частые ошибки

## Ошибка 1

Для нескольких зависимостей складывать их времена.

Нужно:

```text
MAX
```

---

## Ошибка 2

Считать:

```text
start = finish одной случайной зависимости
```

Нужно дождаться:

```text
всех
```

---

## Ошибка 3

Проверять `start <= t < finish`.

Для нумерации миллисекунд, принятой в задачах:

```text
start < t <= finish
```

---

## Ошибка 4

Считать общее время суммой длительностей всех процессов.

При параллельном выполнении это неверно.

---

## Ошибка 5

Забыть, что зависимый процесс может иметь:

```text
несколько предков
```

---

## Ошибка 6

Искать критический путь как цепочку с максимальным количеством процессов.

Важно:

```text
максимальное суммарное ВРЕМЯ,
а не количество вершин.
```

# Универсальный Python для №22

```python
from functools import lru_cache

duration = {
    1: 4,
    2: 6,
    3: 3,
}

deps = {
    1: [],
    2: [],
    3: [1, 2],
}

@lru_cache(None)
def finish(p):
    if not deps[p]:
        return duration[p]

    return (
        duration[p]
        + max(finish(x) for x in deps[p])
    )

start = {
    p: finish(p) - duration[p]
    for p in duration
}

end = {
    p: finish(p)
    for p in duration
}

total = max(end.values())

print("Общее время:", total)
```

```python
parallel = []

for t in range(1, total + 1):
```

# Что ученик обязан вынести

```text
1. Независимый процесс:
   start = 0.

2. Зависимый процесс:
   start = MAX(finish зависимостей).

3. Finish:
   start + duration.

4. Общее время:
   MAX(finish всех процессов).

5. На t-й миллисекунде процесс работает,
   если:
   start < t <= finish.

6. Завершился к T:
   finish <= T.

7. Одновременно работающие процессы
   считаются по готовому расписанию.

8. При нескольких зависимостях
   их времена НЕ складываются.

9. Критический путь —
   самая длинная по времени цепочка зависимостей.

10. @lru_cache(None)
    позволяет удобно вычислить finish
    для большого графа зависимостей.
```

Для цели **60+** №22 стоит свести к одной мысли:

```text
сначала полностью посчитать start/finish,
а уже потом отвечать на конкретный вопрос.
```

После этого большинство разновидностей задания отличаются только последним подсчётом.
