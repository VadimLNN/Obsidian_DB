# Занятие 6. Условие Фано и неравномерное кодирование

**ЕГЭ по информатике — задание №4**

Цель занятия: научиться быстро проверять условие Фано, подбирать недостающие кодовые слова и решать задачи, где нужно минимизировать длину закодированного сообщения.

---

# 1. Что проверяет задание №4

В задании используется **неравномерный двоичный код**.

Это означает, что разные символы могут иметь кодовые слова разной длины.

Например:

```text
А → 0
Б → 10
В → 110
Г → 111
```

Длины кодов:

```text
А → 1 бит
Б → 2 бита
В → 3 бита
Г → 3 бита
```

Такой код удобно использовать, если он позволяет **однозначно декодировать сообщение**.

---

# 2. Условие Фано

Для задач ЕГЭ используется условие:

> **Ни одно кодовое слово не должно быть началом другого кодового слова.**

То есть одно кодовое слово не должно быть **префиксом** другого.

Например:

```text
А → 0
Б → 10
В → 110
Г → 111
```

Условие Фано выполняется.

Почему?

```text
0
```

не является началом кодов:

```text
10
110
111
```

Код:

```text
10
```

не является началом:

```text
110
111
```

и так далее.

---

# 3. Пример неправильного кода

```text
А → 0
Б → 01
В → 10
```

Здесь:

```text
0
```

является началом:

```text
01
```

Поэтому условие Фано **не выполняется**.

Такой набор кодовых слов в задачах №4 использовать нельзя.

---

# 4. Самая простая проверка

Для каждой пары кодов задаём вопрос:

```text
одно слово начинается с другого?
```

Например:

```text
00
010
011
10
```

Проверяем:

```text
00 — не является началом 010
00 — не является началом 011
00 — не является началом 10

010 — не начало 011
010 — не начало 10

011 — не начало 10
```

Следовательно, код допустим.

---

# 5. Удобный способ думать о коде — двоичное дерево

Каждый следующий бит означает переход:

```text
0 → влево
1 → вправо
```

Например:

```text
                начало
               /      \
              0        1
                     /   \
                   10     11
                         /  \
                       110  111
```

Если кодовое слово уже закончилось в некоторой вершине, ниже этой вершины **нельзя размещать другие кодовые слова**.

Например, если уже есть:

```text
А → 0
```

то нельзя использовать:

```text
00
01
000
001
010
011
...
```

потому что все они начинаются с `0`.

---

# 6. Как подобрать одно недостающее кодовое слово

Пусть известны:

```text
А → 0
Б → 10
```

Нужно подобрать код для `В`.

Пробуем короткие слова:

```text
0   — занято
1   — нельзя, потому что является началом 10
00  — начинается с 0
01  — начинается с 0
10  — занято
11  — подходит
```

Ответ:

```text
В → 11
```

---

# 7. Если требуется код минимальной длины

Перебираем слова **по длине**:

```text
длина 1:
0
1

длина 2:
00
01
10
11

длина 3:
000
001
010
011
100
101
110
111
```

Как только встретили допустимое слово — более длинные уже не нужны.

---

# 8. Если требуется минимальное или максимальное числовое значение

Иногда условие говорит:

> найдите код минимальной длины с **минимальным числовым значением**

или:

> ...с **максимальным числовым значением**.

Например, среди трёхбитных слов:

```text
000 = 0
001 = 1
010 = 2
...
111 = 7
```

Поэтому сначала:

```text
1. находим минимально возможную длину;
```

и только потом:

```text
2. выбираем минимальное или максимальное значение среди кодов этой длины.
```

# 9. Главная ловушка задания №4

Пусть известно:

```text
А → 00
Б → 010
В → 011
```

и ещё нужно придумать коды для **четырёх символов**.

Можно заметить:

```text
1
```

само по себе не конфликтует с известными кодами.

Но если назначить одному символу:

```text
1
```

то **вся ветка, начинающаяся с 1, становится закрыта**.

После этого уже невозможно разместить ещё три символа.

Следовательно, при выборе кода нужно проверять не только:

```text
подходит ли он сейчас?
```

но и:

```text
можно ли после этого закодировать все оставшиеся символы?
```

Это одна из типичных ошибок в реальном ЕГЭ.

---

# 10. Пример с несколькими неизвестными символами

Известно:

```text
А → 0
Б → 10
```

Нужно закодировать ещё:

```text
В
Г
```

Нельзя дать:

```text
В → 11
```

а затем пытаться придумать короткий код для `Г`.

После:

```text
0
10
11
```

всё двоичное дерево уже занято.

Поэтому ветку `11` надо разделить:

```text
В → 110
Г → 111
```

Получаем:

```text
А → 0
Б → 10
В → 110
Г → 111
```

---

# 11. Как считать длину закодированного слова

Пусть:

```text
А → 0
Б → 10
В → 110
Г → 111
```

Нужно закодировать:

```text
АБВГА
```

Длины:

```text
А → 1
Б → 2
В → 3
Г → 3
А → 1
```

Общий размер:

```text
1 + 2 + 3 + 3 + 1 = 10 бит
```

---

# 12. Если буква встречается несколько раз

Удобнее считать через частоты.

Например:

```text
А встречается 5 раз, длина кода 1
Б встречается 2 раза, длина кода 3
В встречается 1 раз, длина кода 4
```

Тогда:

```text
I = 5·1 + 2·3 + 1·4
```

```text
I = 15 бит
```

---

# 13. Как минимизировать длину сообщения

Если кодовые слова ещё не заданы полностью, то наиболее часто встречающимся буквам выгодно назначать **более короткие коды**.

Например:

```text
А встречается 10 раз
Б встречается 2 раза
```

Лучше:

```text
А → короткий код
Б → длинный код
```

а не наоборот.

Но условие Фано всё равно должно соблюдаться.

# 14. Алгоритм решения задания №4

## Тип 1. Проверить набор кодов

```text
1. Выписать все кодовые слова.
2. Сравнить каждое с остальными.
3. Проверить, не является ли одно началом другого.
```

---

## Тип 2. Найти код одного символа

```text
1. Начать с длины 1.
2. Перебирать слова этой длины.
3. Проверять условие Фано.
4. Если ничего не подходит — увеличить длину.
```

---

## Тип 3. Осталось несколько неизвестных символов

```text
1. Найти кандидата для нужной буквы.
2. Проверить условие Фано.
3. Проверить, остаётся ли место для остальных букв.
4. Только после этого принимать код.
```

---

## Тип 4. Минимизировать сообщение

```text
1. Посчитать, сколько раз встречается каждая буква.
2. Найти допустимые длины кодовых слов.
3. Более частым буквам дать более короткие коды.
4. Проверить условие Фано.
5. Посчитать общую длину.
```

# 15. Минимальный Python для проверки

Для задания №4 Python обычно **не нужен**, но его можно использовать для проверки.

```python
codes = ["0", "10", "110", "111"]

ok = True

for i in range(len(codes)):
    for j in range(len(codes)):
        if i != j and codes[j].startswith(codes[i]):
            ok = False

print(ok)
```

Результат:

```text
True
```

---

# 16. Удобная функция

```python
def fano(codes):
    for i in range(len(codes)):
        for j in range(len(codes)):
            if i != j and codes[j].startswith(codes[i]):
                return False
    return True
```

Использование:

```python
print(fano(["0", "10", "110", "111"]))
```

Проверять только одинаковые коды.

Нужно проверять не равенство, а **начало слова**.

```text

01
```

Они разные, но:

```text

```

является началом `01`.

---

Найти самый короткий код и сразу записать ответ.

Если остаются другие буквы, нужно проверить, получится ли закодировать их после этого.

---

## Ошибка 4

Сначала выбирать минимальное числовое значение.

Правильно:

```text

→ потом минимальное/максимальное значение
```

---

## Ошибка 5

При минимизации сообщения не учитывать частоту букв.

Частая буква с длинным кодом сильно увеличивает размер сообщения.

# Решения задач 41–50

## 41

Известны:

```text
100011
11101
10101
```

Нужно разместить ещё четыре слова.

Один из оптимальных вариантов:

```text
+ → 01
− → 110
× → 00
/ → 1001
```

Длины:

```text
2 + 3 + 2 + 4 = 11
```

Получить сумму меньше 11 при сохранении условия Фано и четырёх дополнительных кодов нельзя.

**Ответ: 11.**

---

## 42

Известно:

```text
А → 010
Б → 011
Г → 100
```

Можно выбрать:

```text
И → 00
М → 11
Я → 1011
Р → 1010
```

Для слова:

```text
М А Г И Я
```

получаем длины:

```text
2 + 3 + 3 + 2 + 4
```

```text
= 14
```

Важно: `Р` в слове не встречается, но код для неё всё равно должен существовать.

**Ответ: 14.**

## 43

Известно:

```text
Б → 010
Т → 011
```

Оптимально можно использовать, например:

```text

К → 001
Р → 0001
В → 0000
```


```text

Р — 1
```

```text

А: 4 · 1 = 4
Т: 2 · 3 = 6
```

Итого:

```text

```

**Ответ: 20.**

# Как провести занятие за одну пару

Пример на 90 минут:

```text
0–10 мин   — что такое неравномерный код
10–25 мин  — условие Фано + двоичное дерево
25–35 мин  — подбор одного кодового слова
35–45 мин  — несколько неизвестных букв и главная ловушка
45–75 мин  — самостоятельные задачи
75–90 мин  — разбор ошибок
```

## Начинающие

```text
1–20
```

Если успевают:

```text
21–25
```

Главная цель:

```text
научиться видеть конфликт префиксов
```

---

## Средние

```text
11–35
```

Главная цель:

```text
не только проверить код,
но и оставить место остальным буквам
```

---

## Сильные

```text
21–50
```

Особенно:

```text

41–50 — полноценная оптимизация кода
```

# Что ученик должен вынести с занятия

Минимальный набор:

```text
1. Ни одно кодовое слово не является началом другого.

2. Проверять нужно ВСЕ пары кодов.

3. Самый короткий код не всегда можно взять:
   нужно оставить место другим символам.

4. Сначала минимизируем длину кода,
   потом смотрим минимальное/максимальное значение.

5. Чем чаще символ встречается,
   тем выгоднее дать ему короткий код.
```

Для цели курса **60+** этого достаточно, чтобы уверенно работать с основной механикой задания №4.
